第 23 章 ロードバランシング　23-2

どの 1 台に送るか

このページでわかること

実際にどの 1 台に送るかを決める代表的な方式を、2 つ確認する。1 つは要求が来るたびに順番で割り当てる方式、もう 1 つは送信元と宛先の組み合わせから機械的に決める方式である。同じ利用者からの 2 回目の要求が、必ずしも同じ機械に届くとは限らないことも確認する。

このページの目次

かけあい

前のページで、L4 と L7 で見る情報が違うって聞きましたけど、実際にどの機械に送るかは、何を基準に決めてるんですか?

代表的な方式が 2 つあります。1 つは、複数の振り分け先に、要求が来るたびに順番に割り当てていく方式です。前回どこに送ったかだけを見て、次はその次の 1 台に送っていきます。

順番に、ってことは、毎回違う機械に届くんですか?

はい。この方式をラウンドロビンと呼びます。AWS の L7 のロードバランサ(Application Load Balancer)では、初期設定がこの方式です。

L4 のロードバランサも同じ考え方ですか?

違います。L4 のロードバランサには、送信元と宛先の IP アドレスやポート番号などの組み合わせをもとに振り分け先を決める、フローハッシュという方式で決めるものがあります。

組み合わせをもとに、ってどういうことですか?

第 12 章で見たソケット(IP アドレスとポート番号の組)を、送信元側・宛先側の両方について見た組み合わせ、と考えてください。同じ組み合わせが続く間は、同じ振り分け先が選ばれ続けます。

同じ組み合わせが続く、というのはどういうことですか?

同じ TCP 接続の間は、送信元と宛先の組み合わせは変わりません。だから、1 つの接続の間はずっと同じ振り分け先が使われ続けます。

じゃあ、ラウンドロビンとフローハッシュ、選び直す単位が違うってことですか?

そうです。ラウンドロビンは新しい HTTP リクエストのたびに選び直せますが、フローハッシュは接続そのものを単位にしていて、接続の途中で振り分け先を変えることはありません。

なんで、そんな違いがあるんですか?

L7 のロードバランサは HTTP リクエストの区切りが見えるので、リクエスト単位で選び直せます。L4 のロードバランサは接続の中身までは見ておらず、接続全体を 1 つの単位として扱うからです。

じゃあ、同じ人がもう一度接続をやり直したら、前と同じ機械に届くとは限らないんですね。

そのとおりです。接続をやり直すと、送信元のポート番号が変わり、組み合わせが変わるので、別の機械が選ばれることがあります。

何で、接続をやり直すとポート番号が変わるんですか?

接続を始めるとき、送信元側は使っていない番号を一時的に選んで使います。第 12 章で見たエフェメラルポートです。接続をやり直すたびに、この番号が変わることがあります。

同じ人からの 2 回目の要求が、別の機械に届くこともあるってことですね。

そうです。同じ利用者からの要求を毎回同じ機械に送りたい場合には、また別の工夫が要ります。次のページで見ていきましょう。

まとめ

  • 実際にどの 1 台に送るかを決める代表的な方式に、ラウンドロビンとフローハッシュがある。
  • ラウンドロビンは、複数の振り分け先に、要求が来るたびに順番で割り当てていく方式である。AWS の L7 のロードバランサでは、初期設定がこの方式である。
  • フローハッシュは、送信元と宛先の IP アドレスやポート番号などの組み合わせをもとに振り分け先を決める方式で、同じ組み合わせが続く間は同じ振り分け先が選ばれ続ける。
  • ラウンドロビンは新しい HTTP リクエストのたびに選び直せるが、フローハッシュは同じ TCP 接続の間、振り分け先を固定する。
  • 接続をやり直すと送信元のポート番号が変わるため、同じ利用者からの 2 回目の要求が、別の機械に届くことがある。
  • 接続をやり直すと送信元のポート番号(エフェメラルポート)が変わることがあり、フローハッシュの組み合わせも変わりうる。

しくみの話

実際にどの 1 台に送るかを決める方式には、代表的なものが 2 つある。1 つは、複数の振り分け先に、要求が来るたびに順番で割り当てていくラウンドロビンで、AWS の Application Load Balancer(L7 のロードバランサ)では初期設定がこの方式である(#25)。もう 1 つは、送信元と宛先の IP アドレス・ポート番号や、通信の種類(プロトコル)などの組み合わせをもとに振り分け先を決めるフローハッシュで、AWS の Network Load Balancer(L4 のロードバランサ)ではこの方式が使われる(#25)。同じ TCP 接続の間は、送信元と宛先の組み合わせが変わらないため、同じ振り分け先が選ばれ続ける。接続をやり直すと送信元のポート番号が変わり、組み合わせも変わるため、同じ利用者からの接続でも、別の振り分け先が選ばれることがある(#25)。

参考文献

  • [#25] AWS「How Elastic Load Balancing works」 — 原典(92〜121 行目「Routing algorithm」の節。Application Load Balancer の既定は round robin、Network Load Balancer は送信元・宛先の IP アドレスとポート番号、プロトコル、TCP のシーケンス番号を使う flow hash algorithm という記述。「The TCP connections from a client have different source ports and sequence numbers, and can be routed to different targets.」という記述)
