第 25 章 VPC をつなぐ — ピアリング・ハブ・ハイブリッド　25-4

相手のサービスだけを、内側から使う

このページでわかること

相手が用意した特定のサービスだけに、インターネットへ出ずに内側からアクセスできる仕組みがある。相手の VPC のネットワーク全体には届かない。このページでは、この仕組みと、これまでに見た経路との違いを確認する。

このページの目次

かけあい

VPC の外にある、特定のサービスだけを使いたいときって、どうするんですか?

相手が用意した特定のサービスだけに、内側からアクセスできる仕組みがあります。これをPrivateLinkと呼びます。

内側から、っていうのがポイントなんですか?

そうです。こちらの VPC から相手のサービスへ、一方向でアクセスします。相手側から、こちらへ接続してくることはできません。

25-1 で見た VPC ピアリングだと、相手の VPC のネットワークの範囲まで丸ごと届くんでしたよね。

そうです。PrivateLink はそれとは違い、決められた 1 つのサービスへのアクセスだけを許します。相手の VPC の、その他のサーバへは届きません。

第 24 章で見た NAT ゲートウェイ経由でも、外のサービスにアクセスできましたよね。何が違うんですか?

NAT ゲートウェイ経由は、一旦インターネットゲートウェイを通って外のインターネットへ出ます。PrivateLink は、インターネットへ出ずに、相手のサービスまで内側の経路だけで届きます。

インターネットへ出ない分、範囲も限定されているんですね。

そのとおりです。特定のサービスだけを安全に使わせたいときに向いた仕組みです。

個人開発で、VPC ピアリングと同じ感覚で PrivateLink をつないだら、相手の VPC の他のサーバには全然アクセスできなくて驚いたことがあります。

それは正しい挙動です。PrivateLink は、決められた 1 つのサービスだけへの一方向のアクセスを提供する仕組みなので、相手の VPC の他のサーバへは、もともと届かない設計になっています。

知らずに使うと、びっくりしますね。複数のサービスを使いたいときは、どうするんですか?

使いたいサービスの数だけ、それぞれ別に PrivateLink のつながりを用意します。VPC ピアリングや Transit Gateway と、PrivateLink は目的が違う、と覚えておくとよいです。

目的に応じて使い分けるってことですね。次のページでは、ここまでの話を 3 社で比べるんでしたっけ?

そうです。次のページで、AWS・GCP・Azure の呼び方の対応を整理しましょう。

まとめ

  • PrivateLink は、相手が用意した特定のサービスだけに、インターネットへ出ずに内側からアクセスできるようにする仕組みである。
  • PrivateLink は一方向のアクセスで、相手側からこちらへ接続してくることはできない。
  • VPC ピアリングは相手の VPC のネットワークの範囲まで丸ごと届くのに対し、PrivateLink は決められた 1 つのサービスへのアクセスだけを許す。
  • NAT ゲートウェイ経由は一旦インターネットゲートウェイを通って外のインターネットへ出るのに対し、PrivateLink はインターネットへ出ずに内側の経路だけで届く。
  • VPC ピアリングと同じ感覚で PrivateLink をつなぐと、相手の VPC の他のサーバにアクセスできず驚くことがあるが、これは PrivateLink が特定のサービスだけへの一方向のアクセスを提供する仕組みだからで、正しい挙動である。
  • VPC ピアリングや Transit Gateway と PrivateLink は、目的が違う仕組みである。

しくみの話

PrivateLink は、相手が用意した特定のサービスだけに、インターネットへ出ずに内側からアクセスできるようにする仕組みである(#23)。利用側の VPC が、提供側の VPC にある特定のサービスへ一方向でアクセスする形で、利用側でアクセス権のあるクライアントだけが接続を開始でき、提供側から利用側へ接続してくることはできない(#26)。この点で、相手の VPC のネットワークの範囲まで丸ごと届く 25-1 の VPC ピアリングとは異なる。24-4 の NAT ゲートウェイ経由は、一旦インターネットゲートウェイを通って外のインターネットへ出るのに対し、PrivateLink はインターネットへ出ずに、相手のサービスまで内側の経路だけで届く。VPC ピアリングと同じ感覚で PrivateLink をつなぐと、相手の VPC の他のサーバにはアクセスできず驚くことがあるが、これは PrivateLink が決められた 1 つのサービスだけへの一方向のアクセスを提供する仕組みだからであり、正しい挙動である。

参考文献
