第 16 章 DNS の仕組み　16-5

問い合わせの結果を、区画ごとに読み解く

このページでわかること

ここまで、名前解決に関わる役割や、答えの種類、答えの期限を見てきた。名前解決の問い合わせの結果は、いくつかの区画に整理されて表示される。このページでは、その結果を自分の目で確かめる方法を確認する。

このページの目次

かけあい

ここまでリゾルバとか権威サーバとか、いろんな話をしてきましたけど、実際に問い合わせた結果を自分の目で見る方法ってあるんですか?

あります。ターミナルからdig という道具を使うと、問い合わせの結果をそのまま見られます。

結果には何が書かれてるんですか?

いくつかの区画に分かれています。まず、何を尋ねたかを示す区画があります。

尋ねた内容に対する答えは、どこに出るんですか?

答えの区画に出ます。前のページまでに見た DNS レコードが、ここに並びます。

答えの横に、数字が並んでたりするんですか?

並びます。その数字が、前のページで見た DNS の TTL です。

どこに問い合わせたのかも、結果から分かったりするんですか?

分かります。末尾のほうに、問い合わせ先の機械の住所が出ます。この問い合わせは、第 12 章で見た UDP の 53 番という決まった窓口を使って行われます。

自分の家庭用ルータが問い合わせ先になってたりするんですか?

この Mac で実際に確かめたところ、家庭用ルータのアドレスが問い合わせ先になっていました。契約している回線事業者のサーバや、公開されているサーバが問い合わせ先になる構成もあります。

答えが返ってくるまでの時間もわかるんですか?

わかります。応答にかかった時間（ミリ秒）も、結果の末尾に表示されます。

もっと手短に、答えの数字だけ見る方法もあるんですか?

あります。答えの IP アドレスだけを表示する、簡単な聞き方も用意されています。

区画がいくつもあって迷いそうですけど、まず何を見ればいいですか?

まずは答えの区画を見てください。知りたい情報は、たいていそこにそのまま並んでいるので、他の区画は必要になってから見れば十分です。

こういう区画分けって、なんとなく決まった書式があるんですね。

そうです。尋ねた内容の区画と答えの区画が分かれているのは、DNS の問い合わせと応答という決まった形式に沿っているからです。

同じ名前に続けて問い合わせると、DNS の TTL の数字が変わってることもあるんですよね。

そうです。前のページで見たとおり、キャッシュに残っている答えをそのまま使っていれば数字は減り、期限切れで調べ直していれば新しい数字になります。

これで、この章で見てきた仕組みを、自分の目で確かめられましたね。

そうですね。次の章では、この仕組みがうまくいかないときに何が起きるかを見ていきましょう。

まとめ

  • ターミナルから dig という道具を使うと、名前解決の問い合わせの結果をそのまま確認でき、この章で見てきた内容を自分の目で裏付けられる。
  • 結果は区画に分かれており、尋ねた内容の区画と、DNS レコードが並ぶ答えの区画がある。
  • 答えの区画には DNS の TTL の数字も表示され、続けて問い合わせると、キャッシュから答えていれば数字が減り、期限切れで調べ直していれば新しい数字になる。
  • 結果の末尾には、問い合わせ先の機械の住所や、応答にかかった時間も表示される。この問い合わせは第 12 章で見た UDP の 53 番という決まった窓口を使う。
  • 結果の先頭には、問い合わせが正常に処理されたかどうかも示され、答えの数字だけを手短に確認する簡単な聞き方も用意されている。

しくみの話

dig は、ドメイン名に対応する情報を直接問い合わせて調べる、ターミナルのコマンドである。結果の先頭には、問い合わせが正常に処理されたかどうかも示される。結果は、尋ねた内容を示す区画、答えの DNS レコードが並ぶ区画などに分かれて表示される(#71 p.27「DNS Protocol」の Questions／Answers という区画分け)。答えの区画には、前のページで見た DNS の TTL の数字が添えられており、続けて問い合わせたときにこの数字が減っていればキャッシュに残った答えをそのまま使っている証拠であり、増えていれば期限切れで調べ直されたということになる。答えの数字だけを手短に確認する、簡単な聞き方も用意されている。結果の末尾には、問い合わせ先の機械の住所や、応答にかかった時間も表示される。この問い合わせは UDP の 53 番という決まった窓口で行われ、応答が届かない場合は送り直される(#71 p.25「Runs on UDP port 53, retransmits lost messages」)。

試してみよう

dig example.com

見方: 結果はいくつかの区画に分かれている。尋ねた内容の区画には、聞いた名前と型が書かれている。答えの区画には、前のページまでに見た DNS レコードと DNS の TTL の数字が並ぶ。末尾のほうには、この問い合わせをどこに聞きに行ったかと、答えが返ってくるまでにかかった時間が出る。

command not found などで動かなければ、読むだけで進んでよい。
