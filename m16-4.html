第 16 章 DNS の仕組み　16-4

答えには、覚えておいてよい期限がある

このページでわかること

名前解決の答えは、毎回権威サーバまで聞きに行って得ているわけではない。答えには覚えておいてよい秒数の期限があり、複数の場所にその控えが残る。このページでは、この仕組みと、第 1 章で見た事例を正式に説明する。

このページの目次

かけあい

名前解決の答えって、毎回リゾルバが権威サーバまで聞きに行くんですか?

毎回ではありません。答えには、この秒数の間は使ってよいという期限が付いていて、これをDNS の TTL と呼びます。

期限が切れるまでは、聞きに行かなくていいってことですか?

そうです。期限が切れるまでは、前に調べた答えの控えがそのまま使われます。この控えをDNS キャッシュと呼びます。

控えって、どこに残るんですか?

ブラウザ、OS、途中の DNS リゾルバなど、複数の場所に残ります。

あ、それって第 1 章で読んだ、サーバを引っ越したのに古いサーバに繋がり続けたって、あの話と同じ仕組みですか?

そのとおりです。DNS レコードを新しい IP アドレスに変えても、複数の場所に残っていた DNS キャッシュは、DNS の TTL が切れるまでそのまま使われ続けます。

控えのある場所によって、切り替わるタイミングがバラバラだから、時間差が出るんですね。

そうです。すべての控えが新しい答えに入れ替わるまで、見ている場所によって新旧どちらに繋がるか変わることがあります。

第 1 章では、事前に TTL を短くしておくと対策になるって聞きました。

そうです。DNS の TTL を短くしておけば、古い答えの控えが残り続ける時間を短くできます。

第 6 章で見た IP の TTL と、名前は同じだけど別物でしたよね。

そうです。IP の TTL は機械を経由できる残り回数、DNS の TTL は答えを覚えておいてよい秒数で、数えている対象が違います。

DNS の TTL の値って、誰が決めてるんですか?

そのドメイン名の DNS レコードを設定する人が、レコードごとに値を決めます。

短くしすぎると、何か困ることはあるんですか?

あります。問い合わせなくて済む時間が短くなる分、権威サーバや DNS リゾルバへの問い合わせの回数は増えます。

毎回問い合わせなくて済む分、DNS サーバ全体の負担も減るってことですか?

そのとおりです。控えから即座に答えられれば、権威サーバやリゾルバへの問い合わせの回数そのものが減ります。

DNS キャッシュって、いつまでも残り続けるわけじゃないんですよね。

残りません。DNS の TTL が切れれば、控えは捨てられ、次に聞かれたときにもう一度調べ直しに行きます。

なるほど、期限があるからこそ、古い答えを使い続けずに済むんですね。

そうです。次のページでは、実際の問い合わせの結果を自分の目で確かめる方法を見ていきましょう。

まとめ

  • 名前解決の答えには、覚えておいてよい秒数の期限が付いており、これを DNS の TTL と呼ぶ。
  • DNS の TTL が切れるまでは、ブラウザ・OS・途中の DNS リゾルバなどに残った DNS キャッシュの答えがそのまま使われ続ける。
  • 控えは複数の場所にあり、切れるタイミングもバラバラなため、DNS レコードを変更しても、全部が新しい答えに入れ替わるまで時間差が生じることがある（第 1 章 1-2 の事例）。
  • 切り替え前に DNS の TTL を短くしておくと、古い答えが残り続ける時間を短くできる。
  • 第 6 章で見た IP の TTL とは名前が同じだけで、数えている対象（経由できる残り回数か、覚えておいてよい秒数か）が異なる別物である。

しくみの話

名前解決の答えには、覚えておいてよい秒数の期限である DNS の TTL が付いており、この秒数の間、答えはブラウザ・OS・途中の DNS リゾルバといった複数の場所に DNS キャッシュとして残る(#52「What is DNS caching?」の節、#24 の TTL の定義)。DNS の TTL が切れるまでは、控えのある場所はいずれも新しく問い合わせ直さず、手元の答えをそのまま使う(#32「TTL がリゾルバのキャッシュを制御する」)。DNS レコードを新しい IP アドレスに変更しても、複数の場所に残った控えは、それぞれの DNS の TTL が切れるまで使われ続け、控えごとに切れるタイミングが違うため、すべてが入れ替わるまでに時間差が生じる。これが、第 1 章 1-2 で見た「サーバを引っ越したのに、しばらく古いサーバに繋がり続けた」という事例の正体である。控えから答えられる分、権威サーバや DNS リゾルバへの問い合わせの回数は抑えられる(#19「DNS キャッシュサーバ」の節)。

試してみよう

dig example.com
dig example.com

見方: 答えの区画に出てくる数字（DNS の TTL）を、1 回目と 2 回目の実行結果で比べる。数字が減っていれば、キャッシュに残っている答えをそのまま使っている証拠である。逆に増えていれば、期限が切れて調べ直され、新しい期限から数え直されたということである。
