第 15 章 QUIC — UDP 上に作り直したトランスポート　15-4

アドレスやポート番号が変わっても、接続を続けられる仕組み

このページでわかること

今までは、接続を IP アドレスとポート番号の組で識別していたため、利用者がネットワークを切り替えるとそれまでの接続を続けられなかった。QUIC は、接続を別の番号で識別することで、ネットワークが変わっても接続を続けられるようにしている。このページでは、その仕組みと、この章全体の振り返りを確認する。

このページの目次

かけあい

前のページで、初めての相手とは 1 回のやり取りで済むって話でしたけど、接続の途中でネットワークが変わったらどうなるんですか?

良い質問です。今までの TCP では、接続を IP アドレスとポート番号の組で識別していました。

IP アドレスとポート番号の組、ですか?

はい。送信元と宛先、それぞれの IP アドレスとポート番号の組み合わせで、どの接続かを区別していました。

それだと、何か困ることがあるんですか?

利用者がネットワークを切り替えて自分の IP アドレスが変わると、今までとは別の接続として扱われてしまい、接続を作り直す必要がありました。

QUIC だとそこが変わるんですか?

変わります。QUIC は、接続を IP アドレスとポート番号の組ではなく、コネクション ID という番号で識別します。

コネクション ID が同じなら、IP アドレスやポート番号が変わっても同じ接続だと分かるってことですね。

そのとおりです。だから、途中でネットワークが切り替わっても、接続を作り直さずにそのまま続けられます。これをコネクション移行と呼びます。

先輩から聞いた話なんですけど、家を出て Wi-Fi からモバイル回線に切り替わると、動画がいったん止まって再接続していたのに、QUIC を使ったサービスでは途切れずに続いたことがあるそうです。

まさに今の話のとおりです。Wi-Fi からモバイル回線に切り替わると、利用者の IP アドレスが変わります。QUIC はコネクション ID で接続を識別しているので、IP アドレスが変わっても同じ接続だと分かり、作り直さずに続けられたんです。

途中の NAT がポート番号を変えるときも、同じですか?

そうです。途中の NAT がポート番号の対応を変えても、コネクション ID が同じなら、続けられます。第 10 章で見た変換表を思い出してください。

あ、あの変換表ですね。ポート番号が付け替えられることがあるって話でした。

そのとおりです。

この章で見てきた、重なる往復の問題、独立した流れ、往復を減らす仕組み、接続を続けられる仕組みが、全部つながった気がします。

その調子です。もう一つだけ触れておくと、損失を合図に量を減らしたり、帯域と往復時間を測って決めたりする、第 14 章で見た輻輳制御の考え方は、QUIC でも使われます。QUIC は OS の中核部分ではなくアプリ側で動くため、新しい方式にも差し替えやすいんです。

OS を変えなくても、通信のやり方を変えられるってことですね。

そのとおりです。次の章では、名前を数字に変える仕組みを見ていきましょう。

まとめ

  • 今までは、接続を IP アドレスとポート番号の組で識別していたため、利用者がネットワークを切り替えて自分の IP アドレスが変わると、別の接続として扱われ、作り直しが必要だった。
  • QUIC は、接続をコネクション ID という番号で識別する。
  • コネクション ID が同じなら、IP アドレスやポート番号が変わっても、接続を作り直さずに続けられる。これをコネクション移行と呼ぶ。
  • 途中の NAT がポート番号の対応を変えたときも、コネクション ID が同じなら接続は続けられる。
  • 第 14 章で見た輻輳制御の考え方は QUIC でも使われるが、QUIC は OS の中核部分ではなくアプリ側で動くため、新しい方式に差し替えやすい。この章で見た問題と解決策は、こうしてすべてつながっている。

しくみの話

今までの TCP では、接続を送信元・宛先それぞれの IP アドレスとポート番号の組で識別していた。利用者がネットワークを切り替えて自分の IP アドレスが変わると、それまでとは別の接続として扱われ、作り直しが必要になる。QUIC は、接続をこの組ではなく、コネクション ID という番号で識別する。コネクション ID が同じであれば、IP アドレスやポート番号が変わっても同じ接続だと分かり、作り直さずに続けられる。これをコネクション移行と呼ぶ。途中の経路にある NAT がポート番号の対応を変えた場合も同様で、コネクション ID が同じなら接続は続く。第 14 章で見た輻輳制御の考え方(損失を合図に量を減らす、帯域と RTT を測って決める)は、QUIC でも使われるが、QUIC は OS の中核部分ではなくアプリ側で動くため、新しい方式にも差し替えやすい。
