警告が出たら、証明書を確かめる

このページでわかること

ブラウザの警告や curl のエラーという症状を、openssl s_client の証明書チェーンと有効期間、SNI で見分ける。原因の候補は 1 つとは限らない。

このページの目次

かけあい

ケース 2、ブラウザの警告や curl のエラーですね。

31-1 の④、握手の段階です。openssl s_client で証明書を確かめます。

第 19 章 19-1 で、更新を忘れて期限が切れてサイトに警告が出たって話がありましたよね。

そうです。証明書チェーンの NotBefore・NotAfter を見れば、期限切れかどうかがその場で分かります。

NotBefore と NotAfter って、第 18 章 18-3 で見た証明書チェーンの s: と i: とは違うものですか。

別の情報です。s: と i: はチェーンの誰が誰を保証しているかを示し、NotBefore・NotAfter はその証明書の有効期間を示します。

じゃあ、チェーンの方に問題があるケースもあるんですか。

あります。第 18 章 18-3 で見たとおり、証明書チェーンは、上位の証明書へと保証がつながっていく仕組みでした。途中の証明書が欠けていると、ブラウザは一番上の信頼できる証明書までたどり着けず、チェーンを検証できません。

証明書チェーンが途切れるっていうのは、保証のつながりのどこか一段が欠けている状態、ということですか。

そのとおりです。どの段階の保証が欠けていても、ブラウザから見れば同じで、一番上の信頼できる証明書まで検証をたどり着けません。

第 18 章 18-5 で見た、名前不一致の方はどう見分けるんですか。

つなごうとした名前と、証明書に書かれた名前を見比べます。SNI が正しく伝わっていても、サーバ側がその名前用の証明書を持っていなければ起こります。

期限も名前もチェーンも問題ないのに、警告が出ることもあるんですか。

あります。第 19 章 19-4 で見た混在コンテンツです。ページ本体は正しく暗号化されていても、中の一部の部品が http のまま呼び出されていると、その部分だけ警告の対象になります。

握手が成立していても、まだ疑う場所が残っているんですね。

そうです。31-1 の④が正常でも、⑤(応答の中身)の手前で別の原因が残っていることがあります。

証明書チェーン、有効期限、名前不一致、混在コンテンツと、原因の候補がけっこう多いですね。

そうです。だからこそ、証明書そのものの問題(チェーン・期限・名前)と、応答の中身に関わる問題(混在コンテンツ)を、順番に切り分けることが大事なんです。

結局、警告が出たらどの順で確かめればいいんですか。

まず openssl s_client で有効期間とチェーンを確かめ、次に名前が一致しているかを見ます。それでも警告が続くなら、部品の呼び出し先を疑います。

なるほど、握手の内側にも、さらに順番があるんですね。

そのとおりです。

次のケースでは、経路とセキュリティグループを見ていくんですよね。

そうです。次のページで見ていきましょう。

まとめ

  • 証明書の有効期間(NotBefore・NotAfter)が過ぎていれば、握手の段階で期限切れが原因だと分かる。
  • 証明書チェーンが途中で途切れていると、ブラウザは一番上の信頼できる証明書までたどり着けず、検証できない。
  • つなごうとした名前と証明書に書かれた名前が食い違う名前不一致も、握手の段階で確認する。
  • 握手そのものが正常でも、部品が http のまま呼び出される混在コンテンツのように、応答の手前で別の原因が残ることがある。
  • 証明書そのものの問題(チェーン・期限・名前)と、応答の中身に関わる問題(混在コンテンツ)を分けて、順番に確かめるとよい。

しくみの話

第 18 章 18-3 で確立したとおり、証明書チェーンは上位の証明書が下位の証明書を保証する形でつながっており、最後はブラウザや OS があらかじめ信頼している証明書に行き着く(#55、#84)。この保証のつながりが途中で欠けていると、ブラウザは一番上の証明書までたどり着けず、チェーンを検証できない。第 19 章 19-1 で確立したとおり、証明書には有効期間があり、更新の手続きをしないまま過ぎるとブラウザは警告を出す(#21、#87、#90)。第 18 章 18-5 で確立した名前不一致は、つなごうとした名前と証明書に書かれた名前が食い違う場合に起きる(#54、#85)。第 19 章 19-4 で確立した混在コンテンツは、ページの一部の部品が http のまま呼び出されている場合に起きる、握手そのものとは別の原因である(#89、#21)。

試してみよう

openssl s_client -connect example.com:443 -servername example.com </dev/null

見方: Certificate chain の中の NotBefore と NotAfter の行を見る。この日付の範囲を過ぎていれば、31-1 の④の段階のうち、証明書の期限切れが原因だと判断できる。

出力は長めですが、NotBefore と NotAfter を含む行だけを追えば十分。command not found などで動かなければ、読むだけで進んでよい。
