第 20 章 HTTP/1.1　20-1

リクエストとレスポンスは、決まった型で書かれている

このページでわかること

名前解決・接続・暗号化が終わったあと、実際にやり取りされる HTTP のリクエストとレスポンスは、決まった型で書かれた文字の並びである。宛先や中身についての情報がまず並び、区切りをはさんで、実際の中身が続く。このページでは、この並び方を確認する。

このページの目次

かけあい

前の Part の最後で、次は Web を届ける仕組みを見ていくって言われてましたけど、今日から何が変わるんですか?

名前解決・接続・暗号化は、もう終わったという前提で話を進めます。ここからは、実際に交わされる HTTP そのものの中身を見ていきます。

HTTP のリクエストって、決まった形があるんですか?

あります。1 行目に、GET のような HTTP メソッドとパスを書いた行があり、これを要求行と呼びます。

要求行の後は、どうなるんですか?

次に、宛先や中身に関する情報を書いた行が何行か続きます。これがヘッダです。

ヘッダの後は、すぐに本文が始まるんですか?

いいえ。ヘッダが終わったら、空の行を 1 つ挟んでから、本文が続きます。

レスポンスも同じ形なんですか?

似た形です。1 行目が要求行の代わりに、200 のようなステータスコードを含む行になり、これを状態行と呼びます。

状態行の後は、リクエストと同じですか?

そうです。状態行の後にヘッダ、空行、本文と続くのは同じです。

200 の後に OK ってついてますけど、あれは何なんですか?

人が読むための短い説明です。200 OK は成功、404 Not Found は見つからなかった、という意味を、数字と合わせて表しています。

数字と短い説明のセットで、状態行ができているんですね。まるで決まった書式の手紙みたいです。

近い見方です。宛先や差出人の情報を書く部分と、本文とが分かれている点は、確かに手紙の構造に似ています。

じゃあ、ヘッダの後の空行には意味があるんですね。

あります。この空行があるおかげで、ヘッダがどこで終わり本文がどこから始まるかが区別できます。

Web サーバは、どこでこのやり取りを受け付けてるんですか?

多くの場合、80 番か 443 番のポートで待ち受けています。第 12 章で見たとおりです。

Web サーバの中では、どういう手順で処理されるんですか?

接続を受け付け、要求行からパスを取り出し、状態行とヘッダを出力し、指定された中身を出力してから、また最初の状態に戻ります。

なるほど、決まった手順の繰り返しなんですね。

そのとおりです。決まった手順を繰り返すからこそ、実際の通信でもこのとおりになっているか確かめてみましょう。

まとめ

  • HTTP のリクエストは、要求行(HTTP メソッドとパスを書いた行)・ヘッダ・空の行・本文の順に並ぶ。
  • HTTP のレスポンスは、状態行(200 OK のように、ステータスコードと人が読むための短い説明を含む行)・ヘッダ・空の行・本文の順に並び、リクエストと似た型になっている。
  • ヘッダの後の空の行は、ヘッダの範囲と本文の始まりを区別するためにある。
  • Web サーバは、多くの場合 TCP の 80 番(HTTP)か 443 番(HTTPS)のポートで待ち受けている。
  • Web サーバは、接続を受け付け、要求行を読み、状態行とヘッダと中身を返し、また最初の状態に戻るという手順を繰り返している。
  • 要求行・状態行を手紙の宛先や差出人の書き方に、ヘッダをその下に添える送り状になぞらえると、リクエストとレスポンスの型の対応関係を覚えやすい。

しくみの話

HTTP はクライアント・サーバ型のプロトコルで、Web サーバは多くの場合 TCP の 80 番(HTTP)・443 番(HTTPS)のポートで接続を受け付ける(#48)。リクエストは、HTTP メソッドとパスを書いた要求行、宛先や中身に関する情報を並べたヘッダ、空の行、本文という順に並ぶ(#71 p.47)。レスポンスは、要求行の代わりにステータスコードを含む状態行から始まり、その後はヘッダ、空行、本文と続く(#71 p.47)。状態行のステータスコードには、200 OK・404 Not Found のように、人が読むための短い説明が添えられている(#71 p.41)。Web サーバの基本的な動作は、接続を受け付け、要求行からパスを取り出し、状態行とヘッダを出力し、指定された中身を出力してから、また最初の状態に戻るという繰り返しである(#4 p.32)。ヘッダの後に空の行が入るのは、ヘッダの範囲がどこまでで、本文がどこから始まるかを区別するためである。比喩的に言えば、要求行や状態行は手紙の宛先・差出人の書き方にあたり、ヘッダはその下に添える送り状のような情報にあたる。

試してみよう

curl -sv --http1.1 https://example.com -o /dev/null

見方: 出力の中で、> で始まる行(自分が送った側)に要求行・ヘッダ・空行が、< で始まる行(相手から受け取った側)に状態行・ヘッダが並んでいるのを見てください。ここで確認した型が、実際の通信でもそのとおりになっていることが分かります。

出力は行数が多いですが、> と < で始まる行だけを追えば十分です。command not found などで動かなければ、読むだけで進んでよい。
