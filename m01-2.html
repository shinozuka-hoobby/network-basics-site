名前解決の答えは、しばらく覚えられている

このページでわかること

名前解決の答え(ホスト名に対応する IP アドレス)には、この秒数の間は使ってよいという有効期限が付いており、その間は同じ答えが繰り返し使われる。このページでは、対応する IP アドレスを書き換えても、すぐには新しい行き先に切り替わらないことがある理由を確認する。

このページの目次

かけあい

そういえば先輩から聞いた話なんですけど、サーバを新しいところに引っ越したのに、しばらく古いサーバに繋がり続けたことがあるらしいんです。

名前解決自体は成功していたはずですよ。ホスト名と IP アドレスの対応を書いたDNS レコードは、新しい IP アドレスに変えていたんですよね?

はい、変えていたそうです。なのに、なんで古い方に繋がり続けたんですか?

名前解決の答えには、毎回問い合わせなくていいように「この秒数の間は覚えておいてよい」という期限がついていて、これをTTL と呼びます。

じゃあ、その期限が切れるまでは、古い答えのままってことですか?

そうです。TTL が切れるまでは、前に覚えた答えがそのまま使われ続けます。

その「覚えておく」場所って、どこにあるんですか?

ブラウザや OS、途中のDNS サーバなど、複数の場所に控えが残ります。これをキャッシュと呼びます。

ブラウザのキャッシュって、開発者ツールとかで見れたりするんですか?

ブラウザによっては専用の確認画面があります。今日は「複数の場所に控えがある」ということだけ押さえておいてください。

複数の場所に控えがあるなら、全部が新しい答えに入れ替わるまで、時間差が出るってことですね。

その理解で合っています。だから引っ越し直後は、見ている場所によって新旧どちらのサーバに繋がるか変わることがあるんです。

怖いですね…事前に対策とかできないんですか?

できます。引っ越しの前に TTL を短くしておけば、切り替え後に古い答えが残り続ける時間を短くできます。

なるほど、TTL の値自体を事前にいじれるんですね。

そうです。詳しい設定や運用の話は、DNS を専門に扱う第 16 章でまとめて説明します。

ちなみに、TTL の値ってどれくらいが普通なんですか?

サービスによって様々で、数十秒から 1 日程度まで幅があります。値を小さくするほど切り替えは早く終わりますが、その分問い合わせの回数が増えます。

なるほど、短くすればいいってものでもないんですね。

そうです。普段は程よい長さにしておいて、引っ越しのような予定が分かっているときだけ、前もって短くしておくのがよくあるやり方です。

実務では、他にどんな場面でこの仕組みを意識するんですか?

クラウドの DNS サービスを使うときなど、TTL の値を自分で設定する場面があります。詳しくは後の章で扱います。

今日のところは、「名前解決の答えにも期限がある」ってことだけ覚えておけばいいですか?

それで十分です。次のページでは、この名前解決も含めて、旅の途中にどんな機器がいるかを見ていきましょう。

まとめ

  • 名前解決の答えには、この秒数の間は使ってよいという TTL と呼ばれる期限が付いている。
  • TTL が切れるまでは、ブラウザや OS、途中の DNS サーバなどに残ったキャッシュの答えがそのまま使われ続ける。
  • 答えの控えは複数の場所にあるため、DNS レコードを変更しても、全部が新しい答えに入れ替わるまで時間差が生じることがある。
  • 引っ越しなど切り替えの前に TTL を短くしておくと、古い答えが残り続ける時間を短くできる。
  • この仕組みは毎回問い合わせをさばく必要を減らし、DNS サーバ全体の負荷を抑えることにもつながる。名前解決の失敗とは別の理由で、意図しない相手に繋がることがある、という点が重要である。

しくみの話

DNS の問い合わせ先には複数の役割があり、ブラウザや OS がまず自分の手元の控え(キャッシュ)を確認し、無ければ外部の DNS サーバに尋ねに行く(#52)。DNS サーバの側も、一度調べた答えを TTL で指定された秒数の間だけ覚えておき、その間の問い合わせには自分の控えから即座に答える。TTL が切れると、DNS サーバは答えの出どころに改めて確認しに行き、新しい答えと TTL を受け取る。ブラウザ、OS、途中の DNS サーバがそれぞれ別のタイミングでキャッシュしているため、DNS レコードを変更しても、すべての控えが新しい答えに入れ替わるまでは時間差が生じる。事前に TTL を短く設定しておけば、この時間差を短くできる。この仕組みは、多くの利用者からの同じ問い合わせを毎回さばかずに済むという利点もあり、DNS サーバ全体の負荷を抑えることにもつながる。運用の現場では、切り替えの影響範囲を見積もるために、事前に現在の TTL の値を確認しておくことが多い。

試してみよう

host example.com

見方: 「has address」の行に、ホスト名に対応する IP アドレスが出る。これが名前解決の答え、つまりしばらくキャッシュに残る値そのものである。
