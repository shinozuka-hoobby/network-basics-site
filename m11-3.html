第 11 章 IPv6　11-3

新しい IP アドレスは、機械が自分で組み立てることもできる

このページでわかること

新しい形式の IP アドレスを使い始めるには、第 4 章で見た DHCP のようにサーバから配ってもらう方法だけでなく、機械が自分でアドレスを組み立てて使い始める方法もある。このページでは、この 2 つの方法を確認する。

このページの目次

かけあい

第 4 章 4-3 で見た DHCP、新しい形式の IP アドレスでも同じように番号をもらうんですか?

そのやり方もありますが、新しい形式には、機械が自分でアドレスを組み立てる方法もあります。これを SLAAC と呼びます。サーバに毎回頼らなくて済みます。

自分で組み立てるって、どうやってですか?

ネットワーク側から届く情報と、機械自身の情報(MAC アドレスなど)を組み合わせて作ります。DHCP のようにサーバに頼らなくても、機械だけでアドレスを完成させられます。

じゃあ、いつも自分で組み立てるだけなんですか?

実はもう 1 つ、電源を入れた時点で必ず作る番号があります。同じネットワークの中だけで通じる、リンクローカルアドレスと呼ばれる番号です。通信できる相手がまだいなくても、これは自分で作ります。

世界中で通じる番号じゃなくて、同じネットワークの中だけなんですね。

そうです。世界中で通じる番号(グローバルユニキャストアドレスと呼びます。第 5 章で見たグローバルアドレスと同じ考え方です)は、ネットワーク側から届く情報をもとに、別に組み立てます。

DHCP と同じように、サーバが配る方法も新しい形式にはあるんですか?

あります。DHCPv6 と呼ばれる仕組みです。第 4 章 4-3 で見た DHCP と同じように、サーバが機械にアドレスを配り、名前解決の問い合わせ先のような追加の情報も一緒に配ります。

SLAAC と DHCPv6、実際にはどちらが使われるんですか?

両方使われることがあります。新しい形式だけの環境を試した合宿の報告でも、両方使われていました。ただ、うまくいかない場面もありました。

どんな場面だったんですか?

よくある事例なんですが、古い OS(Windows XP や Mac OS X 10.6 以前)を使っていた参加者が、DHCPv6 に対応していないために名前解決の問い合わせ先を自動で受け取れず、手作業で設定する必要があったそうです。

なんで、番号自体はもらえたのに、そっちは自動で受け取れなかったんですか?

SLAAC によって機械は自分でアドレスを組み立てられますが、名前を IP アドレスに変換する仕組みの問い合わせ先のような、追加の情報までは自分で用意できません。この追加の情報を配るのが DHCPv6 の役目ですが、当時のこれらの OS は DHCPv6 に対応していなかったため、手作業が必要になりました。

なるほど、アドレス自体と、それ以外の情報とでは、担当が違うんですね。

そのとおりです。次のページでは、新しい形式へ切り替えが進む間、どうやって今までの形式とやり取りするのかを見ていきましょう。

まとめ

  • 新しい形式の IP アドレスは、DHCP のようにサーバから配ってもらう方法だけでなく、機械が自分で組み立てる方法(SLAAC)でも使い始められる。
  • SLAAC では、ネットワーク側から届く情報と機械自身の情報を組み合わせて、機械が自分でアドレスを作る。
  • 機械は電源を入れた時点で、同じネットワークの中だけで通じるリンクローカルアドレスを必ず自分で作る。世界中で通じるアドレスは別に組み立てる。
  • DHCP と同じようにサーバがアドレスを配る仕組み(DHCPv6)もあり、名前解決の問い合わせ先のような追加の情報も配る。実際のネットワークでは、両方が使われることがある。

しくみの話

新しい形式の IP アドレスを使い始める方法には 2 つある。1 つは、機械がネットワーク側から届く情報と、自分自身の情報(MAC アドレスなど)を組み合わせてアドレスを組み立てる SLAAC である(#67)。機械は電源を入れた時点で、同じネットワークの中だけで通じるリンクローカルアドレスを必ず自分で作り、世界中で通じるアドレス(グローバルユニキャストアドレス)は、ネットワーク側から届く情報をもとに別に組み立てる。もう 1 つは、第 4 章 4-3 で見た DHCP と同じように、サーバが機械にアドレスを配る DHCPv6 である。実際のネットワークでは、SLAAC と DHCPv6 の両方が使われることがある(#16)。DHCPv6 は、アドレスに加えて、名前解決の問い合わせ先のような追加の情報を配る役目も持つ。古い OS の一部は DHCPv6 に対応しておらず、SLAAC でアドレス自体は得られても、この追加の情報だけは自動で受け取れないことがあった(#16)。

試してみよう

ifconfig

見方: 実行結果の中に、「inet6」に続いて「fe80:」から始まる番号の行がある。これが、このページで見たリンクローカルアドレスであり、ネットワークに他の機械がいるかどうかに関わらず、機械が自分で作っている番号である。

複数の「fe80:」行が出ることもあるが、少なくとも 1 行あることを確認できれば十分である。
