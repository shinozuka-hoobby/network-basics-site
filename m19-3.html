第 19 章 HTTPS を運用する　19-3

常に HTTPS でつなぐようブラウザに覚えさせる

このページでわかること

http でアクセスされたとき、https へ誘導するだけでは、実は最初の 1 回のアクセスまでは守り切れない。このページでは、この弱点と、ブラウザに毎回 https でつながせる仕組みを確認する。

このページの目次

かけあい

http でアクセスしても、https に誘導してくれるサイトがありますよね。あれで十分守られてるんじゃないんですか?

実は、最初の 1 回だけは守られません。

え、なんでですか? ちゃんと https に誘導されてるのに。

その誘導自体が、最初は暗号化されていない http のやり取りとして送られています。だから最初の 1 回だけは、途中で書き換えられたり中身を見られたりする隙が残ります。

先輩から、公共の Wi-Fi で、最初につないだ瞬間に変なサイトに誘導されたことがあるって聞いたことがあります。

まさに、その隙を突かれた例だと思います。最初の http のやり取りは暗号化されていないので、途中で誘導先を書き換えられることがあります。

じゃあ、これを守る方法はあるんですか?

あります。一度 https で正しく接続できたときに、応答の中に「次からは必ず https で接続してほしい」という指示を含めておく方法です。これを HSTS と呼びます。

その指示を覚えていれば、次からは http にすら行かなくなるってことですね。

そのとおりです。ブラウザが覚えていれば、次回以降はブラウザ自身が最初から https で接続します。

覚えた指示は、ずっと有効なんですか?

指示には有効な期間が指定されていて、その間はブラウザが覚え続けます。期間が過ぎれば、また最初から確認し直します。

さっきの応答の中の指示って、どこに書かれてるものなんですか?

応答に添えられる情報の一部に書かれています。細かい形式は、後の章でまとめて扱います。

一度も訪れたことが無いサイトだと、この指示はまだ効いてないですよね?

そのとおりです。初めて訪れるときは、まだ指示を受け取っていないので、最初の 1 回の弱点がそのまま残ります。

じゃあ、有名なサイトなら平気なんですか?

有名かどうかは関係ありません。大事なのは、そのブラウザがそのサイトの指示を過去に受け取って覚えているかどうかです。

https ということは、TLS の手続きも毎回行われるんですよね?

そうです。HSTS が指示するのは「https を使うかどうか」で、https の中身である TLS の手続き自体は、これまで見てきたとおりです。

最初の 1 回だけはどうしようもないけど、2 回目以降は守れるってことなんですね。

そのとおりです。次のページでは、また別の弱点を見ていきましょう。

まとめ

  • http でのアクセスを https へ誘導するだけでは、その誘導自体が暗号化されていない http のやり取りとして送られるため、最初の 1 回は守られない。
  • 公共の Wi-Fi などでは、この最初の隙を突かれて、別のサイトに誘導される例がある。
  • 一度 https で正しく接続できたとき、応答の中に「次からは必ず https で」という指示を含めておく仕組みを HSTS と呼ぶ。
  • ブラウザがこの指示を覚えていれば、次回以降は最初から https で接続する。指示には有効な期間があり、期間が過ぎればまた最初から確認し直す。
  • 一度も訪れたことが無いサイトには、まだ指示が届いていないため、最初の 1 回の弱点がそのまま残る。サイトの知名度とは関係が無い。

しくみの話

http でのアクセスを https へ誘導するだけでは、その誘導自体が暗号化されていない http のやり取りとして送られるため、最初の 1 回のアクセスは、途中で書き換えられたり中身を見られたりする隙が残ったままになる。HSTS は、一度 https で正しく接続できたときに、応答の中に「次からは必ず https で接続してほしい」という指示を含めておくことで、この隙を補う仕組みである。ブラウザがこの指示を覚えていれば、次回以降はブラウザ自身が最初から https で接続するようになり、2 回目以降のアクセスはこの隙を避けられる。指示には有効な期間が指定されており、その間はブラウザが覚え続ける。この指示はサイトごとに記憶されるため、一度も接続したことが無いサイトには届いておらず、最初の 1 回の弱点はそのまま残る。これはサイトの知名度とは関係が無く、そのブラウザが過去に指示を受け取っているかどうかで決まる。HSTS が指示するのは https を使うかどうかであり、https の中身である TLS の手続き自体を変えるものではない。

試してみよう

curl -sI https://<あなたのサイト>

見方: 応答の中に strict-transport-security という行があるかどうかを見てください。この行があれば、そのサイトはブラウザに「次からは必ず https で」と指示しています。行が無ければ、その指示はしていません。

サイトによっては行が無いこともあり、それも観察の結果です。command not found などで動かなければ、読むだけで進んでよい。
