第 13 章 TCP の接続と信頼性　13-5

今、この接続はどの段階にいるか

このページでわかること

TCP の接続は、待ち受け中・会話中・閉じた直後など、いくつかの段階のどれかにあり、段階によって機械の振る舞いが変わる。このページでは、この段階の区分と、片側が接続を閉じたあともしばらく「閉じた直後」の段階が残ることを確認する。

このページの目次

かけあい

ここまでで、あいさつが終わる前、会話中、終わりの合図を送った直後、といういろんな場面が出てきましたね。

そうです。これらは全部、接続が今どの段階にあるかを表す区分の一部で、TCP の状態遷移と呼びます。

1 章から今日まで、ずっとこの状態遷移の中を進んできたってことなんですね。

そのとおりです。会話できる状態を作る前、作った後、終えた後、それぞれ別の段階として扱われています。

具体的にはどんな段階があるんですか?

代表的なものとして、まだ申し出を待っている段階(LISTEN、待ち受け中)、実際に会話できている段階(ESTABLISHED、会話中)、閉じた直後の段階(TIME_WAIT、閉じた直後)があります。他にも、あいさつの途中などいくつか細かい段階があります。

待ち受け中と会話中は、何が違うんですか?

待ち受け中は、まだ相手からの申し出(SYN)を待っているだけの段階です。会話中は、あいさつが終わり、実際にデータをやり取りできる段階です。

段階によって、機械の振る舞いって具体的にどう変わるんですか?

例えば、待ち受け中の段階でデータそのものが届いても、機械はまだそれを受け取る準備ができていません。段階ごとに、受け付けられる合図の種類が決まっています。

先輩から、サーバを再起動した直後に、同じポートで待ち受けを始められなかったって聞いたことがあります。

よくある事例です。接続を能動的に閉じた側は、閉じた直後もしばらくの間、閉じた直後の段階を保ち続けます。

なんで、閉じたのにすぐ次の待ち受けを始められないんですか?

その段階が残っている間は、同じ組み合わせでの接続にすぐには使いにくいためです。前の接続の後始末が、まだ完全には終わっていないと考えてください。

この段階って、どれくらいの間残るんですか?

一定の時間だけ残り、それが過ぎると消えます。具体的な仕組みはここでは立ち入りませんが、決して無限に残り続けるわけではありません。

再起動してすぐ待ち受けを始めたい場合、どうすればいいんですか?

少し時間を空けて待つのが基本です。設定で回避する方法もありますが、それも含めて細かい対処はここでは扱いません。

自分の Mac でも、今どんな段階の接続があるか見れたりするんですか?

見れます。会話中・閉じた直後・待ち受け中、それぞれの段階にある接続の数を、あとで試してみましょう。普段は意識しない数字が、実は結構な数になっていることに驚くかもしれません。

これで、会話できる状態を作って、番号を付けて届いたことを確かめて、届かなければ送り直して、終わるときは手順を踏む、という TCP の基本が一通り揃いましたね。

そうです。次の章では、この接続の上でデータをやり取りするとき、確認を待たずにどんどん送ってよいのか、送れるとしたらどれだけの量か、という話を見ていきます。

まとめ

  • 接続は、待ち受け中(LISTEN)・会話中(ESTABLISHED)・閉じた直後(TIME_WAIT)など、いくつかの段階(TCP の状態遷移)のどれかにあり、段階ごとに受け付けられる合図の種類が決まっている。
  • 待ち受け中はまだ相手からの申し出を待っている段階、会話中は実際にデータをやり取りできる段階である。
  • 接続を能動的に閉じた側は、閉じた直後もしばらくの間、閉じた直後の段階(TIME_WAIT)を保ち続ける。
  • 閉じた直後の段階が残っている間は、同じ組み合わせでの接続にすぐには使いにくい。

しくみの話

TCP の接続は、待ち受け中(LISTEN)、あいさつの途中、実際に会話できる会話中(ESTABLISHED)、そして接続を閉じた直後(TIME_WAIT)など、いくつかの段階のどれかにあり、この区分を TCP の状態遷移(コネクションの状態)と呼ぶ(#4 p.15、p.18〜19)。段階が変わるきっかけは、SYN・ACK・FIN といった合図の送受信であり、同じ合図でも今どの段階にいるかによって機械の振る舞いが変わる(#4 p.18〜19)。接続を能動的に閉じた側は、閉じた直後も一定の時間、閉じた直後の段階を保ち続ける(#4 p.15)。これは、古い接続の遅れて届いたデータを、あとから同じ組み合わせで作られる新しい接続と混同しないためである。この段階が残っている間は同じ組み合わせでの接続にすぐには使いにくいため、サーバを再起動した直後に同じポート番号で待ち受けを始めようとして、うまく始められないことがある。

試してみよう

netstat -an -p tcp | grep -c ESTABLISHED
netstat -an -p tcp | grep -c TIME_WAIT
netstat -an -p tcp | grep -c LISTEN

見方: 3 つの数字は、今この Mac にある接続のうち、会話中・閉じた直後・待ち受け中の段階にあるものが、それぞれいくつあるかを示す。TIME_WAIT の行の数字が 0 でなければ、それがこのページで説明した「閉じた直後の段階がしばらく残る」ことの実例である。
