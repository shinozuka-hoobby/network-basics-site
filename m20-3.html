第 20 章 HTTP/1.1　20-3

接続を使い回す

このページでわかること

1 つのやり取りごとに、通信のための道筋を新しく作り直していると、その分の時間がかかってしまう。このページでは、この無駄を避けるために、一度作った道筋を次のやり取りにも使い回す仕組みを確認する。

このページの目次

かけあい

第 13 章で、TCP 接続を作るのに 3 回のやり取りが要るって習いましたけど、Web ページを開くたびに毎回それをやってるんですか?

昔はそうでした。1 つのリクエストごとに、いちいち新しい TCP 接続を作り直していたんです。

1 つのページに画像が何枚もあったら、その分だけ接続を作るってことですか? 大変そうです。

そうです。1 つのオブジェクトを取得するたびに新しい接続を開く方式を、非持続的な HTTP と呼びます。

さっきから出てくるオブジェクトって、具体的には何のことですか?

HTML 本体や、その中に埋め込まれた画像・CSS ファイルなど、1 つ 1 つの部品のことです。

非持続的な方式って、今はもう使われていないんですか?

非持続的な方式は古い HTTP/1.0 の方式で、この章で見ている HTTP/1.1 では、持続的な方式が基本になっています。

接続を作るたびに、何が余分にかかるんですか?

接続を作る往復が、オブジェクトの数だけ繰り返し発生します。

往復が増えると、どれくらい遅くなるんですか?

非持続的な場合、合計の時間はオブジェクトの数掛ける、2 倍の往復時間足す転送時間になります。

先輩から、API を毎回別の接続で呼んでいたら遅かったって聞いたことがあります。

まさにそれです。呼び出しの数だけ、接続を作る往復が積み重なっていたんだと思います。

この無駄を避ける方法があるんですか?

あります。一度作った接続を、やり取りが終わってもすぐには切らず、次のやり取りにも使い回す仕組みが考えられました。これを Keep-Alive と呼びます。

接続を使い回すと、何が変わるんですか?

最初に接続を開く往復は 1 回で済み、2 番目以降のオブジェクトは、その接続をそのまま使います。

じゃあ、合計の時間はどう変わるんですか?

持続的な場合、合計の時間は往復時間 1 回足す、オブジェクトの数掛ける往復時間足す転送時間になります。

接続を使い回せば、その分の往復が省けるってことですね。

そのとおりです。実際に使い回されているところを確かめてみましょう。

使い回した接続は、いつか切れるんですか?

はい。しばらくやり取りが無ければ切れますし、どちらかが明示的に切ることもあります。

まとめ

  • オブジェクトとは、HTML 本体やその中の画像・CSS ファイルなど、1 つ 1 つの部品のことである。非持続的な HTTP(古い HTTP/1.0 の方式)は、この 1 つ 1 つを取得するたびに新しい TCP 接続を開くため、オブジェクトの数だけ接続を作る往復が繰り返し発生する。
  • 一度作った接続を、やり取りが終わってもすぐには切らず、次のやり取りにも使い回す仕組みを Keep-Alive と呼ぶ。
  • Keep-Alive を使う持続的な HTTP(この章で扱う HTTP/1.1 の基本方式)では、最初に接続を開く往復は 1 回で済み、2 番目以降のオブジェクトはその接続をそのまま使う。
  • API を毎回別の接続で呼んでいたケースは、呼び出しの数だけ接続を作る往復が積み重なっていたために遅かったと考えられる。
  • 使い回された接続も、しばらくやり取りが無ければ切れ、どちらかが明示的に切ることもある。

しくみの話

オブジェクトとは、HTML 本体や、その中に埋め込まれた画像・CSS ファイルなど、1 つ 1 つの部品を指す。1 つのオブジェクトを取得するたびに新しい TCP 接続を開く方式を、非持続的な HTTP と呼び、これは古い HTTP/1.0 の方式にあたる(#71 p.37)。この場合、合計の応答時間はオブジェクトの数 ×(2 × 往復時間 + 転送時間)になり、オブジェクトが増えるほど、接続を作る往復の回数も増えていく(#71 p.38)。1 回のリクエストのたびにファイルの種類ごとに TCP 接続を確立し直す必要があり、アクセス数が増えるとサーバの負荷も大きくなる(#4 p.5〜6)。この無駄を避けるため、一度作った接続をやり取りが終わってもすぐには切らず、次のやり取りにも使い回す仕組みが Keep-Alive である。この章で扱う HTTP/1.1 では、持続的な HTTP が基本になっており、最初に接続を開く往復は 1 回で済み、合計の応答時間は往復時間 + オブジェクトの数 ×(往復時間 + 転送時間)になる(#71 p.39)。

試してみよう

curl -sv https://example.com https://example.com -o /dev/null -o /dev/null

見方: 出力の中に "Re-using existing connection" という行があるかを見てください。この行があれば、2 回目の要求で新しい接続を作らず、1 回目の接続をそのまま使い回した証拠です。

出力は行数が多いですが、"Re-using existing connection" の行だけを探せば十分です。command not found などで動かなければ、読むだけで進んでよい。
