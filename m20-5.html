第 20 章 HTTP/1.1　20-5

応答を控えておく

このページでわかること

ブラウザや途中のサーバは、一度受け取った答えの控えを保存しておき、次に使うことがある。このページでは、この控えがどれくらいの間使われるかを Web サーバがどう指示するかを確認する。

このページの目次

かけあい

前のページで、Keep-Alive でも順番待ちの問題は残るって聞きましたけど、他にも工夫できることはあるんですか?

あります。ブラウザや途中のサーバが、一度受け取った応答の控えを保存しておいて、同じ要求への答えとして再利用することがあります。これを HTTP キャッシュと呼びます。

控えを再利用するって、第 16 章で見た DNS キャッシュと同じような話ですか?

控えておいて使うという考え方は同じですが、控える対象が違います。DNS キャッシュは名前解決の答え、こちらは Web サーバの応答そのものです。

応答を控えておけば、毎回 Web サーバまで問い合わせずに済むんですね。

そのとおりです。控えが使えれば、応答時間も Web サーバの負担も減らせます。

途中のサーバっていうのは、具体的にはどんな機械なんですか?

利用者と Web サーバの間に置かれ、みんなの代わりに控えを持っておく機械のことです。会社のネットワークの出口などに置かれることがあります。

逆に、控えちゃいけないっていう指示もできるんですか?

できます。使ってよい期間を指定するだけでなく、そもそも控えてはいけないという指示もできます。

個人開発で、画像を更新したのに、しばらく古い画像が表示され続けたことがあります。

それはまさに、この HTTP キャッシュの仕業だと思います。

なんで、更新したのに古い画像のままだったんですか?

ブラウザや途中のサーバに残った控えが、指示された期間はそのまま使われ続けるからです。

指示、ですか? 誰が指示するんですか?

Web サーバが応答に添える指示で決まります。この指示を Cache-Control と呼び、例えば「この秒数までは使ってよい」という指定ができます。

その秒数を過ぎるまでは、ずっと古いままなんですね。

そうです。だから、画像を更新しても、その期間が過ぎるまでは古い控えが表示され続けることがあります。

指定した秒数を過ぎたら、もう一度全部取りに行くんですか?

そうとも限りません。前と変わっていないかだけを問い合わせて、変わっていなければ控えをそのまま使い続ける、条件付きの取り直しという方法もあります。

変わっていないか確認するだけなら、全部を送り直すより速そうですね。

そのとおりです。控えを上手に使えば、速さと最新さのバランスを取れます。

この章で見てきた話が、これで一通りつながりました。

そのとおりです。次の章では、HTTP がどう進化していったかを見ていきましょう。

まとめ

  • ブラウザや途中のサーバが、一度受け取った応答の控えを保存しておき、同じ要求への答えとして再利用する仕組みを HTTP キャッシュと呼ぶ。
  • 控えておいて使うという考え方は第 16 章の DNS キャッシュと同じだが、控える対象が違う(名前解決の答えか、Web サーバの応答か)。
  • Web サーバが応答に添えて、この内容をどれくらいの間、控えとして使ってよいかを指示する項目を Cache-Control と呼ぶ。
  • 画像を更新しても、Cache-Control で指示された期間はブラウザや途中のサーバの控えがそのまま使われ続けるため、古い内容が表示され続けることがある。
  • 期間が過ぎても、前と変わっていないかだけを確認する条件付きの取り直しによって、控えをそのまま使い続けられる場合がある。

しくみの話

ブラウザは、すべてのリクエストを途中の控え(キャッシュ)経由で送るよう設定でき、控えが近くにあれば応答時間を短縮でき、Web サーバや回線の負荷も減らせる(#71 p.45)。こうした途中のサーバは、利用者と Web サーバの間、例えば会社のネットワークの出口などに置かれ、複数の利用者の代わりに控えをまとめて持つ(#71 p.45)。この、応答の控えを保存しておいて同じ要求への答えとして再利用する仕組みを HTTP キャッシュと呼ぶ。控えをどれくらいの間使ってよいか、あるいはそもそも控えてよいかどうかは、Web サーバが応答に添える Cache-Control という項目で指示され(#71 p.46)、この指示に従う期間は、内容を更新しても古い控えがそのまま使われ続けることがある。指示された期間が過ぎても、前と変わっていないかだけを問い合わせ、変わっていなければ本文を送り直さずに控えをそのまま使う、条件付きの取り直しという方法もある(#71 p.47)。

試してみよう

curl -sI https://example.com

見方: age: という行の数字を見てください。これは、この応答がどこかの控えに保管されてから経過した秒数です。この数字が 0 より大きければ、控えから返ってきた証拠です。

age: の行が無いサイトもあり、それも観察の結果です。command not found などで動かなければ、読むだけで進んでよい。
