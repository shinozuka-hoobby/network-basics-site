第 20 章 HTTP/1.1　20-2

主要なヘッダ

このページでわかること

リクエストとレスポンスに添えられている、宛先や中身についての情報の並びには、いくつか代表的な項目がある。このページでは、その項目が何を伝えているかを確認する。

このページの目次

かけあい

前のページでヘッダの話が出てきましたけど、あれって具体的には何が書かれてるんですか?

ヘッダには、コロンで区切られた名前と値の組が並びます。これをまとめて HTTP ヘッダと呼びます。

コロンで区切られた名前と値、ですか?

はい。例えば Host という名前の後にコロンを挟んで、example.com のような値が続きます。

他には、どんな名前があるんですか?

リクエストなら、宛先のホスト名を伝える Host、ブラウザの種類を伝える User-Agent などがあります。

Accept みたいなヘッダも見たことあるんですけど、あれも仲間ですか?

はい。ブラウザがどんな形式の返事を望んでいるかを伝えるヘッダで、User-Agent と同じく、ブラウザの側から伝える情報の一つです。

レスポンス側にもあるんですか?

あります。本文の種類を伝える Content-Type、本文の長さを伝える Content-Length などです。

Host って、URL に書いてあるホスト名と同じですよね? なんでヘッダにも書くんですか?

良いところに気づきました。前のページで見た要求行にはパスしか書かれていないので、宛先のホスト名は Host ヘッダの方に書く決まりになっています。

なるほど、要求行だけでは宛先が分からないってことですね。

そのとおりです。Web サーバは Host ヘッダを見て、どの宛先向けのリクエストかを判断します。

あ、そういえば第 19 章で見た、https を強制する指示(HSTS)って、どこに書かれてたんでしたっけ?

まさにそれも、この HTTP ヘッダの一つです。応答の中の指示、と言っていたものは、正式には HTTP ヘッダに書かれていたんです。

ヘッダって、全部でどれくらいの種類があるんですか?

実際には数多くの種類がありますが、まずは今日見た代表的な項目を押さえておけば十分です。

じゃあ、ヘッダって結構いろんな役割があるんですね。

そうです。宛先を伝えるもの、中身の性質を伝えるもの、指示を伝えるものなど、役割はさまざまです。

実際にどんな項目が並んでいるか、見てみたいです。

試してみましょう。実際の応答を見れば、こうした項目がいくつも並んでいるのが分かります。

ヘッダを見れば、いろんな情報が分かるんですね。

そのとおりです。次のページでは、この接続をどう使い回すかを見ていきましょう。

まとめ

  • リクエストとレスポンスのヘッダには、コロンで区切られた名前と値の組が並ぶ。これをまとめて HTTP ヘッダと呼ぶ。
  • リクエストの要求行にはパスしか書かれていないため、宛先のホスト名は Host ヘッダに書く決まりになっている。
  • User-Agent はブラウザの種類、Accept はブラウザが望む返事の形式、Content-Type は本文の種類、Content-Length は本文の長さを伝える。
  • 第 19 章で見た、次からは必ず HTTPS でつないでほしいという指示(HSTS)も、HTTP ヘッダの一つとして応答に添えられている。
  • ヘッダの役割は、宛先を伝えるもの、ブラウザの情報を伝えるもの、中身の性質を伝えるもの、指示を伝えるものなど、項目によってさまざまである。

しくみの話

HTTP ヘッダは、コロンで区切られた名前と値の組が並ぶ部分で、リクエストにもレスポンスにも付けられる(#71 p.46)。リクエストの要求行にはパスしか書かれていないため、宛先のホスト名は Host ヘッダに書く決まりになっており、Web サーバはこれを見て宛先を判断する(#71 p.47)。ほかにも、ブラウザの種類を伝える User-Agent、ブラウザが望む返事の形式を伝える Accept、本文の種類を伝える Content-Type、本文の長さを伝える Content-Length などがある(#71 p.46)。第 19 章で見た、次からは必ず HTTPS でつないでほしいという指示(HSTS)も、この HTTP ヘッダの一つとして応答に添えられている。HTTP メッセージがメソッドやヘッダといった要素を持つという構造は、HTTP のバージョンが変わっても共通している(#20)。ヘッダには数多くの種類があるが、宛先・中身の種類・ブラウザの情報など、代表的なものを押さえておくと、通信の中身を読み解きやすい(#71 p.46)。

試してみよう

curl -sI https://example.com

見方: 1 行目のプロトコルの版は気にせず、その後に続く「名前: 値」の形の行を見てください。content-type: のような行が、ここで説明した HTTP ヘッダです。

command not found などで動かなければ、読むだけで進んでよい。
