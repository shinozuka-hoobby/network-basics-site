第 18 章 TLS と PKI　18-3

その身分証を、誰が本物だと保証しているのか

このページでわかること

Web サーバは、通信の相手に、自分が名乗っている相手であることを示す身分証を見せる。この身分証は、信頼できる機関が審査したうえで保証の印を付けたものであり、その機関自体が信頼できるかどうかも、さらに上の機関の保証をたどって確かめられる。このページでは、この身分証の仕組み全体を確認する。

このページの目次

かけあい

前のページで、公開鍵をどうやって信頼して受け取るのか、次で答えるって言ってましたよね?

はい。サーバは、自分が名乗っている相手であることを示す身分証を見せます。この身分証には、通信で使う公開鍵も入っています。

その身分証、サーバが自分で勝手に作って名乗ればいいんじゃないですか?

それでは信頼できません。身分証は、信頼できる機関に申請して発行してもらいます。この機関を認証局と呼びます。

認証局は、何を審査するんですか?

申請してきた相手が、本当にその名前(サーバ)の正当な持ち主かどうかを審査します。

審査を通れば、認証局はその相手のために身分証を発行し、そこに保証の印を付けます。

その印があれば、ブラウザは無条件に信じるんですか?

いいえ。ブラウザは、印を付けた認証局自体が信頼できるかどうかも確かめます。

その認証局が信頼できるかどうかは、どう確認するんですか?

認証局自身の身分証も、さらに上位の認証局から保証を受けています。この保証のつながりを証明書チェーンと呼びます。

じゃあ、それをどこまでもさかのぼっていくんですか?

たどっていくと、最後は誰の保証も受けずにそれ自体が信頼されている身分証、つまり一番上の身分証に行き着きます。

ブラウザや OS は、あらかじめこの一番上の身分証を少数だけ信頼する形で持っています。

公開鍵と、この身分証と、それを保証する機関を全部まとめて呼ぶ名前ってあるんですか?

あります。この仕組み全体を PKI と呼びます。

実際にこの仕組みが崩れた事件とかあるんですか?

あります。ある認証局がハッキングを受け、正規の審査を経ずに、別の相手向けの身分証を発行してしまった事件がありました(DigiNotar 事件)。

なんでそんなことが起きると、危ないんですか? 身分証は認証局が保証してるはずですよね?

認証局自身が乗っ取られると、本来なら審査で弾かれるはずの申請を通してしまい、不正な相手にも身分証と保証の印を発行してしまいます。

その身分証は正規の手順を通ったものと見分けがつかず、本物のサイトになりすまして通信を盗聴される可能性がありました。

身分証を実際にいつ確認するのかは、次のページで見るんですよね?

そのとおりです。次のページでは、この身分証の確認と鍵の取り決めの手続きの流れを見ていきましょう。

まとめ

  • Web サーバは、自分が名乗っている相手であることを示す身分証(TLS 証明書)を提示する。身分証には公開鍵が含まれる。
  • 身分証は、信頼できる機関(認証局)に申請して発行してもらう。認証局は、申請してきた相手が本当にその名前の正当な持ち主かどうかを審査し、通れば身分証を発行して保証の印を付ける。
  • 認証局自身の身分証も、さらに上位の認証局から保証を受けている。この保証のつながりを証明書チェーンと呼び、たどると、最後はブラウザや OS があらかじめ信頼している身分証に行き着く。
  • 公開鍵・身分証・それを保証する機関を組み合わせて、相手が本物かどうかを確かめられるようにする仕組み全体を PKI と呼ぶ。
  • ある認証局がハッキングを受け、正規の審査を経ずに身分証を発行してしまった事件があった(DigiNotar 事件)。認証局自体が乗っ取られると、不正な身分証も正規の手順を通ったものと見分けがつかなくなる。

しくみの話

Web サーバは、自分が名乗っている相手であることを示す身分証(TLS 証明書)を提示し、この身分証には公開鍵が含まれる。身分証は、信頼できる機関(認証局)に申請して発行してもらうもので、認証局は、申請してきた相手が本当にその名前の正当な持ち主かどうかを審査し、通れば身分証を発行して保証の印を付ける。認証局自身の身分証も、さらに上位の認証局から保証を受けており、この保証のつながりを証明書チェーンと呼ぶ。たどっていくと、最後は誰の保証も受けずにそれ自体が信頼されている身分証(一番上の身分証)に行き着き、ブラウザや OS はあらかじめこの一番上の身分証を少数だけ信頼する形で持っている。公開鍵・身分証・それを保証する機関を組み合わせて、通信の相手が本当に名乗っている相手かどうかを確かめられるようにする、この仕組み全体を PKI と呼ぶ。ある認証局がハッキングを受け、正規の審査を経ずに別の相手向けの身分証を発行してしまった事件があった(DigiNotar 事件)。認証局自体が乗っ取られると、本来なら審査で弾かれるはずの申請を通してしまい、不正な身分証も正規の手順を通ったものと見分けがつかなくなる。

試してみよう

openssl s_client -connect example.com:443 -servername example.com </dev/null

見方: 実行結果の Certificate chain の並びを見てください。各段の s: がその段の身分証が誰のものか、i: がそれを誰が保証したかを表しています。ある段の i: が、その 1 つ上の段の s: と一致していることを確認してください。これが、このページで見た証明書チェーンの実物です。

出力は長めですが、Certificate chain の見出しの下の s: と i: の行だけを追えば十分です。command not found などで動かなければ、読むだけで進んでよい。
