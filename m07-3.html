第 7 章 ARP と同一ネットワーク内の通信　7-3

パケットが宛先に届くまでを、順番に追う

このページでわかること

前の 2 ページで見た、同じサブネットかどうかの判定と、IP アドレスから MAC アドレスを調べる仕組みを、1 回の送信の流れとしてつなげる。宛先 MAC アドレスと宛先 IP アドレスが、別サブネット宛てのときに別の動き方をすることを確認する。

このページの目次

かけあい

前の 2 ページ、同じサブネットかどうかの判定と、ARP で MAC アドレスを調べる話でしたけど、1 回の送信としてつなげて見るとどうなるんですか?

順番に整理しましょう。同じサブネットの相手に送る場合と、別のサブネットの相手に送る場合とで、途中から流れが分かれます。

同じサブネットの相手だったら、ARP で直接その相手の MAC アドレスを調べて送るんですよね。

そうです。そのときは、宛先 MAC アドレスも宛先 IP アドレスも、その相手そのものになります。

別サブネットだったら、宛先 MAC アドレスはデフォルトゲートウェイになるってことですか? でも宛先 IP アドレスは...?

宛先 IP アドレスは変わりません。最終的な相手のままです。変わるのは、次に渡す隣の機器を指す宛先 MAC アドレスだけです。

なるほど、フレームの宛先とパケットの宛先が別だったのは、こういうことだったんですね。第 1 章で聞いたときは、まだピンと来てなかったです。

今なら分かるはずです。宛先 MAC アドレスは次に渡す隣の機器、宛先 IP アドレスは最終的な相手を指す番号です。

じゃあその先、デフォルトゲートウェイが受け取ったあとはどうなるんですか?

そこから先はルータの仕事です。宛先 IP アドレスを見て、次にどこへ渡すか判断します。中身は第 8 章で扱います。

第 1 章 1-4 で、ヘッダが付く順番はトランスポート層、インターネット層、ネットワークインターフェース層の順だって、クイズで見た気がします。

よく覚えていますね。IP アドレスを扱うのがインターネット層、MAC アドレスを扱うのがネットワークインターフェース層です。この 2 つの層がちょうど接するところで、今日の判定と付け替えが起きています。

あ、第 5 章で、サブネットマスクを間違えて「別のネットワークにいる」と判定しちゃう話がありましたよね。その続きが分かった気がします。

そうです。判定を誤ると、本当は同じ部屋にいる相手なのに、ARP で直接調べる代わりにデフォルトゲートウェイの MAC アドレスを調べて渡そうとしてしまいます。

宛先 IP アドレスは正しいままなのに、もったいないですね。

そのとおりです。本来同じ部屋で済むはずの通信が、いったんデフォルトゲートウェイを経由しようとして、届かなかったり遅れたりすることがあります。

じゃあ最初から最後まで、もう一度流れを整理してもらえますか?

いいですよ。しくみの話で、番号付きの手順としてまとめておきます。

分かりました。これで、宛先 MAC アドレスと宛先 IP アドレスの違いが、やっと自分の言葉で説明できそうです。

それは何よりです。次の章では、デフォルトゲートウェイに渡した先、ルータの中で何が起きているかを見ていきましょう。

まとめ

  • 同じサブネットの相手に送るときは、宛先 MAC アドレスも宛先 IP アドレスも、その相手そのものになる。
  • 別のサブネットの相手に送るときは、宛先 MAC アドレスがデフォルトゲートウェイのものに変わる一方、宛先 IP アドレスは最終的な相手のまま変わらない。
  • 宛先 MAC アドレスは次に渡す隣の機器を指す番号、宛先 IP アドレスは最終的な相手を指す番号であり、この違いは IP アドレスを扱うインターネット層と MAC アドレスを扱うネットワークインターフェース層の接点にあたる。
  • 同一サブネットかどうかの判定を誤ると、本当は同じサブネットにいる相手なのに、デフォルトゲートウェイ経由で送ろうとしてしまうことがある。
  • デフォルトゲートウェイが受け取った先、ルータの中で何が起きるかは第 8 章で扱う。

しくみの話

1 つのパケットが送り出されるまでの流れは、次の 6 段階として整理できる(#65)。

  1. 送信元ホストが、宛先 IP アドレスと自分のサブネットマスクから、宛先が同じサブネットにいるかどうかを判定する。
  2. 同じサブネットなら ARP で宛先本人の MAC アドレスを、別サブネットなら ARP でデフォルトゲートウェイの MAC アドレスを調べる。
  3. 調べた MAC アドレスを宛先 MAC アドレスにしてフレームを送り出す。宛先 IP アドレスは最終的な相手のまま変わらない。
  4. 別サブネット宛てのとき、デフォルトゲートウェイがフレームを受け取り、中の宛先 IP アドレスを見る(#47)。
  5. デフォルトゲートウェイは、宛先 IP アドレスに応じて次に渡す機器を選び、新しい宛先 MAC アドレスを付け直してフレームを作り直す。
  6. これを繰り返し、最終的に宛先 IP アドレスと一致するホストにフレームが届く。

途中の地点ごとに宛先 MAC アドレスが変わる一方、宛先 IP アドレスは変わらない様子は、パケットトレーサーのような演習でも確認できる(#43)。

試してみよう

netstat -rn

見方: 「default」で始まる行にある番号を見る。これが、このページで説明したデフォルトゲートウェイの、実際の IP アドレスである。第 4 章 4-2 で見た「まず送り出される先」と同じものである。

command not found などで動かなければ、読むだけで進んでよい。
