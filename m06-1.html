第 6 章 IP パケットと配送の仕組み　6-1

パケットの中に書かれていること

このページでわかること

第 1 章では、IP アドレス宛ての情報のかたまりを「パケット」と呼ぶことを確認した。ここでは、その中に実際にどんな情報が書き込まれているかを見ていく。送信元と宛先の IP アドレスだけでなく、全体の大きさや中身の種類を示す情報も一緒に書き込まれている。

このページの目次

かけあい

第 1 章で、IP アドレス宛ての情報のかたまりがパケットだって聞いたんですけど、あの中には実際に何が書いてあるんですか?

まず、送信元と宛先の IP アドレスが書かれています。

宛先だけでいいんじゃないんですか? 届けばそれで十分な気がします。

宛先だけだと、相手はどこに返事を送り返せばいいか分かりません。だから送信元の IP アドレスも一緒に書かれているんです。

たしかに、返事がもらえないと困りますね。

他にも、このかたまり全体の大きさを示す「全長」という情報が書かれています。

大きさまで書いておく必要があるんですか?

途中の機械が、どこまでが 1 つのかたまりなのかを判断するのに使います。長さが分からないと、次のかたまりとの境目が分かりません。

境目が分からないと、何が困るんですか?

次のパケットの先頭を、今のパケットの続きだと勘違いしてしまうかもしれません。全長は 16 ビット(0 か 1 のひと桁が 16 個並んだもの)の数字で表されていて、IP パケット全体の大きさは最大でも 65,535 バイトまでしか表せません(#71)。

なるほど、境目を示す情報でもあるんですね。

そしてもう 1 つ、中身がどんな種類のやり取りかを示す番号もあります。

中身の種類って、何が入ってるかによって変わるものなんですか?

はい。詳しい種類は後の章(第 12 章・第 13 章)で扱いますので、ここでは、そういう番号もある、ということだけ押さえてください。

他にも書いてある数字ってあるんですか?

あります。あと何回機械を経由できるかを表すIP の TTLという数字もその一つです。詳しくは 6-2 で見ていきましょう。

送信元、宛先、大きさ、中身の種類、TTL…けっこう色々書いてあるんですね。

これらをまとめて IP ヘッダと呼びます。第 1 章で見た、データの前に付け足す宛先などの情報という説明を覚えていますか?

はい、覚えてます。あの「ヘッダ」の、IP の分がこれってことですね。

そのとおりです。この IP ヘッダと、その後ろに続く中身をあわせたひとかたまり全体を、あらためてIP パケットと呼びます。

1-4 で見たパケットを、もう少し詳しく見た感じですね。

そうです。1-4 では「IP アドレス宛ての情報を持ったひとかたまり」という大まかな説明でしたが、その中身が今日見た IP ヘッダだった、という関係になります。

封筒の中の、住所欄や中身の説明欄を細かく見た感じですね。

近いです。次のページでは、TTL が実際にどう働くかを詳しく見ていきましょう。

まとめ

  • IP パケットの IP ヘッダには、送信元と宛先の IP アドレスが書かれている。
  • パケット全体の大きさを示す情報も書かれており、途中の機械はこれを見てかたまりの境目を判断する。
  • 中身がどんな種類のやり取りかを示す番号や、あと何回機械を経由できるかを示す TTL という数字も書かれている。
  • これらの情報(IP ヘッダ)と中身をあわせたひとかたまり全体を、IP パケットと呼ぶ。
  • 全長は 16 ビットの数字であり、IP パケット全体は理論上最大 65,535 バイトまで表せる。

しくみの話

IP ヘッダ(送信元/宛先 IP アドレス、全長、TTL、プロトコル番号など) → データ

IP パケットは、IP ヘッダと呼ばれる部分と、その後ろに続く中身(データ)からできている。この並び順は、フレームの中に IP パケットが入り、IP パケットの中にヘッダと中身が入るという、第 1 章 1-4 の封筒の図・第 3 章 3-1 のフレームの図と同じ向きである。IP ヘッダは、追加の項目(オプション)が無ければ 20 バイトの大きさになる(#3、#71)。主な項目は次のとおり。

項目内容
送信元 IP アドレスどの機械から送られたかを示す
宛先 IP アドレスどの機械に届けるかを示す
全長この IP パケット全体の大きさ(バイト数)
TTLあと何回機械を経由できるかを示す数字
プロトコル番号中身がどんな種類のやり取りかを示す番号

この章では、現在広く使われている IPv4 を前提に説明する。宛先だけでなく送信元も書かれているのは、相手が返事を送り返せるようにするためである。全長は、途中の機械が次のパケットとの境目を判断するために必要であり、これが無ければパケットどうしを正しく区切れない。プロトコル番号も、宛先の機械が中身をどう扱えばよいかを判断する手がかりとして使われている。

試してみよう

curl -sI https://example.com

見方: 1 行目に HTTP のバージョンと 200 のようなステータスコードが返ってくる。この応答も、内側に今日見た IP パケットが使われて届いている。

command not found などで動かなければ、読むだけで進んでよい。
