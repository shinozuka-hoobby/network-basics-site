第 25 章 VPC をつなぐ — ピアリング・ハブ・ハイブリッド　25-5

3 社で、呼び方はこう変わる

このページでわかること

25-1 から 25-4 で見た呼び方は、いずれも AWS のものである。GCP・Azure では呼び方や、確認できた資料の厚みが違う。このページでは、3 社の対応を 1 つの表で整理する。

このページの目次

かけあい

ここまで AWS の言葉で見てきましたけど、GCP や Azure だとどう呼ぶんですか?

呼び方が違うだけのものが多いです。表で整理しましょう。

VPC ピアリングは、GCP だと VPC Network Peering って呼ぶんですね。制約も同じですか?

そうです。GCP の VPC Network Peering も、推移しないことと、互いの IP アドレスの範囲が重ならないことが必要な点は同じです。

Transit Gateway や共有 VPC は、GCP だとどう呼ぶんですか?

Transit Gateway に近いのは Network Connectivity Center、共有 VPC はそのまま Shared VPC と呼びます。

VPN や専用線は?

VPN に近いのは Cloud VPN、専用線に近いのは Cloud Interconnect です。PrivateLink に近いのは Private Service Connect と呼びます。

GCP の Cloud VPN って、AWS の VPN と全く同じ役目なんですか?

大まかには同じですが、GCP の資料には、Cloud VPN を、Transit Gateway のように中心に集めてつなぐ「ハブ＆スポーク」の中継ぎとして使える、という記述もあります。3 社で細部まで完全に一致するわけではありません。

Azure の列に「—」が多いのが気になります。

Azure にも同じ役目のサービスの見出しはあるのですが、収集した資料には仕組みを説明した本文までは含まれていませんでした。

無いってことじゃなくて、確認できていないってことですか?

そのとおりです。無いと決まったわけではなく、確認できていない、という意味だと考えてください。

表を見ると、共有 VPC と VPC ピアリングの行だけ、Azure の名前が全く無いんですね。

そこも同じ理由です。索引にも見出しが見つかりませんでした。

呼び方や資料の厚みは違っても、解決している問題自体は共通しているんですね。

そのとおりです。この章で見た 4 つの答え、VPC ピアリング・ハブ・VPN や専用線・PrivateLink を、用途と制約で選び分けられるようになれば、この章の目標は達成です。次は第 26 章で、ネットワークセキュリティの基礎を見ていきましょう。

まとめ

  • AWS の VPC ピアリングに近いのは、GCP の VPC Network Peering である。Azure には対応する記述が見つからなかった。
  • AWS の Transit Gateway に近いのは、GCP の Network Connectivity Center である。
  • AWS の共有 VPC に近いのは、GCP の Shared VPC である。Azure には対応する記述が見つからなかった。
  • AWS の VPN・専用線に近いのは、GCP の Cloud VPN・Cloud Interconnect である。
  • AWS の PrivateLink に近いのは、GCP の Private Service Connect である。
  • Azure の列の「—」は、仕組みを説明した本文が収集資料に見つからなかったことを意味し、無いと決まったわけではない。
  • GCP の Cloud VPN には、ハブ＆スポークの中継ぎとして使えるという記述もあり、3 社で細部まで完全に一致するわけではない。
