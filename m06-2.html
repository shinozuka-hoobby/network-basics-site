第 6 章 IP パケットと配送の仕組み　6-2

届く保証はないけれど、あきらめずに届けようとする

このページでわかること

IP は、送ったデータが必ず届くことを約束していない。できる範囲で精一杯届けようとするだけという考え方のうえに成り立っている。このページでは、この考え方と、際限なく迷い続けるパケットを防ぐために書き込まれている、経由できる機械の数の上限について確認する。

このページの目次

かけあい

IP って、送ったら必ず相手に届けてくれるものだと思ってました。

実は、必ず届けるという保証はしていないんです。

え、そうなんですか? 届かないことがあるのに、それでいいんですか?

はい。IP は、できる範囲で精一杯運ぼうとするだけで、届いたかどうかの確認までは行いません。この考え方をベストエフォートと呼びます。

じゃあ、届いたかどうかの確認は誰がやってるんですか?

その確認は別の仕組み(第 13 章で扱います)の仕事です。ここではまず、IP 自身は保証をしない、という考え方を押さえてください。

保証がないなら、パケットが迷子になって、ネットワークの中をずっとさまよい続けることもあるんじゃないですか?

良いところに気づきましたね。そうならないための歯止めが、パケットには書き込まれています。

歯止めって、どんなものですか?

あと何回機械を経由できるかを表す数字で、IP の TTLと呼びます。経由するたびに 1 ずつ減り、0 になると、その時点の機械がパケットを捨てます。

TTL の初期値って、いくつに設定されるものなんですか?

機械の種類によって違いますが、IP の TTL は 8 ビット(0 か 1 のひと桁が 8 個並んだもの)の数字なので、0〜255 の 256 通りの値しか表せません。そのため、初期値には 64 や 255 のような値がよく使われます(#65)。

その、経由する機械って何なんですか?

送られてきたパケットの宛先を見て、次にどの機械へ渡すかを決める機械で、ルータと呼びます。詳しくは第 8 章で扱います。

名前だけ聞くと、第 1 章 1-2 で見たDNS の TTLと同じですよね?

似ていますが別物です。DNS の TTL は名前解決の答えの有効期限で、こちらは機械を経由できる回数です。同じ略語でも、指しているものが違います。

ややこしいですね…同じ名前を使うのはなぜなんですか?

どちらも「これ以上は古い」「これ以上は先に進めない」という上限を表す考え方が共通しているためです。詳しくは第 16 章で扱います。

実際に、TTL が尽きて届かなかったことなんてあるんですか?

よくある事例を紹介します。ある現場で経路の設定を誤り、2 台の機械が互いに相手へパケットを転送し合う状態になったことがありました。

え、それってパケットがずっと行ったり来たりし続けるってことですか?

そうです。もし TTL という上限がなければ、そのパケットは消えずに残り続けてしまいます。しかし経由するたびに TTL が 1 ずつ減っていくため、上限に達した時点で機械がパケットを捨て、宛先に届かないまま消えました。

保証がないのも困りものですけど、歯止めがあるのは安心ですね。

次のページでは、パケットの大きさに関する別の上限を見ていきましょう。

まとめ

  • IP は、データが必ず届くことを保証しない。できる範囲で精一杯届けようとするだけであり、これをベストエフォートと呼ぶ。
  • 届いたかどうかの確認は、IP 自身ではなく別の仕組み(第 13 章)が行う。
  • パケットが際限なくさまよい続けないよう、あと何回機械(ルータ)を経由できるかを示す IP の TTL という数字が書き込まれている。
  • IP の TTL は経由するたびに 1 ずつ減り、0 になると機械がそのパケットを捨てる。第 1 章で見た DNS の TTL とは別物である。
  • IP の TTL は 8 ビットの数字であり、0〜255 の範囲しか表せない。初期値には 64 や 255 のような値がよく使われる。

しくみの話

IP の TTL は、パケットが送り出される時点であらかじめ数字が設定され、機械を 1 台経由するたびに 1 ずつ減っていく(#50)。0 になった時点で、その機械はパケットをそれ以上転送せず捨てる。ベストエフォートという考え方のもとでは、IP は届ける努力はするが、届いたかどうかを送信元に自動で知らせることはしない。第 1 章で見た DNS の TTL は名前解決の答えの有効期限を数える数字だったが、IP の TTL は経由できる機械の残り回数を数える数字であり、数える対象がまったく違う。IP の TTL は 8 ビットの数字として書かれており、表せる範囲は 0〜255 に限られる(#71)。経路の設定ミスでパケットが行き来し続けた事例(#65)でも、初期値である 255 を上限に、それ以上は機械を経由できずに捨てられる。

試してみよう

ping -c 3 example.com

見方: 出力に含まれる「ttl=」に続く数字を見る。これは、相手に届くまでの間に、まだこれだけ機械を経由できる余力が残っていたことを示す値である。経由した機械の実際の台数や経路そのものを見る方法は第 27 章で扱う。

command not found などで動かなければ、読むだけで進んでよい。
