送った内容と、受け取った内容を、記号で見分ける

このページでわかること

curl でリクエストを送れることはすでに知っているだろうが、付け足すオプションによって見える範囲が変わる。送受信の経過をまとめて表示するオプションを使うと、行の先頭の記号で内容を見分けられる。このページでは、これまでの章で使ってきたオプションと、その記号の読み方を整理する。

このページの目次

かけあい

curl -sI はこれまで何度も使ってきましたけど、curl -sv の方は正直、行が多すぎて何を見ればいいか分からなかったです。

-v を付けると、送った内容と受け取った内容が、接続の経過も含めて表示されます。行の先頭の記号を見分けると読みやすくなります。

記号って、どんな種類があるんですか。

> が自分が送った内容、< が相手から受け取った内容、* が接続や暗号化の経過などの補足情報です。

第 18 章で見た Client hello とか Server hello は、どの記号に入るんですか。

* の行に入ります。TLS のハンドシェイクの経過も、この補足情報として表示されているんです。

第 20 章や第 21 章で見た HTTP/2 200 とか content-type: みたいな行は、どの記号ですか。

< の行に入ります。相手から受け取った応答の中身だからです。

じゃあ、自分が送った要求の中身を見たいときは、> の行を探せばいいんですね。

そのとおりです。ほかに { と } という記号もあり、それぞれ受け取ったデータの中身、送ったデータの中身を表します。量が多いので、実際の中身ではなくバイト数だけが表示されることもあります。

-I だけだと、これは分からないんですか。

-I は相手から返ってきたヘッダだけを見る方法で、自分が送った内容や、接続・暗号化の経過は表示されません。-v を使えば、そのすべてを記号で見分けながら確認できます。

-s は何のためのオプションだったんですか。

進捗の表示などを消して、結果だけを見やすくするためのオプションです。今まで使ってきた -sI や -sv の s の部分がそれです。

-o /dev/null をよく付けてましたけど、あれは何のためだったんですか。

応答の中身の保存先を指定するオプションで、/dev/null を指定すると、中身を捨てて画面には出さないようにできます。

--http1.1 を付けたこともありましたよね。

使う HTTP のバージョンを指定するオプションです。既定のバージョンと違う版で試したいときに使います。

これで 4 つの道具の出力が読めるようになりましたけど、実際に問題を切り分けるときは、どの順で使えばいいんですか。

それは第 31 章でまとめて扱います。今日のところは、それぞれの道具で何が分かり、何が分からないかを押さえておいてください。次の章では、これらの道具よりもさらに細かく、実際にやり取りされている中身そのものを覗く方法を見ていきます。

まとめ

  • curl -v を付けると、送った内容と受け取った内容が、接続の経過も含めて表示される。
  • 行の先頭の記号で見分ける。> は自分が送った内容、< は相手から受け取った内容、* は接続や暗号化の経過などの補足情報である。
  • 第 18 章で見た TLS ハンドシェイクの経過は * の行、第 20・21 章で見た応答のステータス行やヘッダは < の行に入る。
  • -I は相手から返ってきたヘッダだけを見る方法で、送った内容や接続の経過までは表示されない。
  • -s は進捗などの表示を消すオプション、-o は応答の保存先を指定するオプション、--http1.1 は使う HTTP のバージョンを指定するオプションである。

しくみの話

curl に -v を付けると、送受信の経過が記号付きで表示される。行頭の > は自分が送った内容、< は相手から受け取った内容、* は接続や暗号化の経過などの補足情報を表す(#106 -v, --verbose の節)。ほかに、{ は受け取ったデータの中身、} は送ったデータの中身を表す記号として用意されている(#106 -v, --verbose の節)。第 18 章で見た TLS ハンドシェイクの Client hello や Server hello は * の行に、第 20・21 章で見た応答のステータス行(例えば HTTP/2 200)やヘッダ(content-type: など)は < の行に、それぞれ含まれる。-I(#106 -I, --head の節)は相手から返ってきたヘッダだけを取得する方法で、自分が送った内容や接続の経過までは表示されない。-s(#106 -s, --silent の節)は進捗などの表示を消し、-o は応答の保存先を指定する。--http1.1(#106 --http1.1 の節)は、使う HTTP のバージョンを指定する。

試してみよう

curl -sv https://example.com -o /dev/null

見方: 各行の先頭の記号に注目する。> は自分が送った内容、< は相手から受け取った内容、* は接続や暗号化の経過などの補足情報である。

出力は長いが、行頭の記号だけを追えば十分。command not found などで動かなければ、読むだけで進んでよい。
