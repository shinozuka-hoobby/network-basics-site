第 29 章

クラウド上の経路診断

この章で分かること

  • クラウドの診断機能が、実際にはパケットを送らずに、設定を読み取って「届くはずか」を言い当てる仕組みを説明できる。
  • AWS・GCP・Azure、3 社の診断機能の名前と、それぞれが「設定を読むだけ」か「実際に送る機能も持つ」かを言える。
  • 実際に通った通信や、止められた通信を記録しておく仕組み(送信元・宛先・許可か拒否かなど)を説明できる。
  • 推論と記録を組み合わせて、第 24・25 章で見た事例のどこを直すべきかを確かめ直せる。

中心図

 +---------------------------+
 |      クラウドの区画          |
 | (ルートテーブル・区画の境目の |
 |  設定など)                  |
 +---------------------------+
        |               |
        | 設定を読む      | 実際に通信が流れる
        v               v
 +--------------+   +----------------+
 | 届くはずかを   |   | 通った・止めら  |
 | 言い当てる     |   | れた跡を記録   |
 +--------------+   +----------------+
        |               |
        +-------+-------+
                v
      +----------------------+
      |   どこを直すか決める    |
      +----------------------+

クラウドの区画の設定を読んで「届くはずか」を言い当てる道と、実際に通った・止められた跡を記録しておく道の、2 つを突き合わせて、どこを直すか決める。
