第 27 章 観測ツール入門 — ping・traceroute・dig・curl　27-1

届くか、届かないかを、まず確かめる

このページでわかること

相手まで通信が届くかどうかを確かめる方法の 1 つに、短い確認の合図を送って応答を待つやり方がある。合図が返ってこなくても、相手の機械が止まっているとは限らない。このページでは、この確認の道具の出力の読み方と、分かること・分からないことを整理する。

このページの目次

かけあい

ここまでの章で ping というコマンドを何度か実行してきましたけど、そもそも何をしているコマンドなんですか。

第 6 章 6-4 で見た ICMP を使って、相手まで通信が届くかどうかと、届くまでの時間を確かめる道具で、ping と呼びます。宛先に短い確認の合図を送り、同じ種類の返事が戻ってくるかを見ています。

実行結果に icmp_seq= とか ttl= とか time= とか、色々並んでますよね。全部見た方がいいんですか。

行ごとに役目が違います。icmp_seq= は何回目の確認かを示す番号、ttl= は第 6 章 6-2 で見た IP の TTL の残りです。

じゃあ、今日はどこを見ればいいんですか。

time= に続く数字と、最後にまとめて出る統計の行に注目しましょう。time= は、確認の合図を送ってから返事が戻るまでの時間で、第 2 章 2-2 で見た往復時間そのものです。

統計の行って、何が書かれているんですか。

送った回数、受け取った回数、届かなかった割合、それに往復時間の最小・平均・最大が並びます。

届かなかった割合があるってことは、届かないこともあるんですね。届かなかったら、相手の機械が止まってるってことですか。

そうとも限りません。第 6 章 6-4 で見た事例を覚えていますか。経路の途中の設定で ICMP の合図そのものが遮断されて、原因の切り分けが難しかった話です。

はい、覚えてます。あれって ping にも関係あるんですか。

あります。その現場は、経路の途中の設定が ICMP の合図をまるごと拒否していたので、もし ping で確かめていたとしても、宛先の機械自体は正常なのに応答は返ってこなかったはずです。

機械は動いてるのに、ping だけ失敗するんですね。

そうです。ping が確かめているのは ICMP のやり取りだけなので、途中で ICMP が遮断されていると、宛先が正常でも失敗します。届かない、イコール相手が止まっている、とは言えないんです。

じゃあ、Web サーバが動いてるかどうかも ping で分かるんですか。

それも分かりません。ping が確かめるのは ICMP の往復だけで、第 12 章で見たポート番号ごとのサービスが動いているかどうかは別の話です。

じゃあ、Web サーバの入り口が開いているかを確かめたいときは、どうするんですか。

第 12 章 12-1 で使った、ポート単位で確かめる別の道具が向いています。しくみの話で、実際のコマンドの形を確認しましょう。

なるほど、道具によって確かめられることが違うんですね。

そのとおりです。次のページでは、途中の機械を 1 台ずつ確かめる道具を見ていきましょう。

まとめ

  • ping は、ICMP を使って相手まで通信が届くかどうかと、届くまでの時間を確かめる道具である。
  • 実行結果の icmp_seq= は確認の回数、ttl= は IP の TTL の残り、time= は往復時間を示す。
  • 末尾の統計行には、送った回数・受け取った回数・届かなかった割合・往復時間の最小/平均/最大が並ぶ。
  • 応答が返らなくても、相手の機械が止まっているとは限らない。経路の途中で ICMP の合図だけが遮断されている場合がある。
  • ping が確かめるのは ICMP の往復だけで、特定のサービス(例えば Web サーバ)が動いているかどうかは別の話である。

しくみの話

ping は、宛先に ICMP のエコー要求という合図を送り、エコー応答が戻ってくるかどうかで通信が届くかを確かめる(#46)。この Mac で確認したところ、実行結果には icmp_seq=(要求ごとの番号)、ttl=(届いた時点で残っていた IP の TTL の値)、time=(要求を送ってから応答が戻るまでの往復時間)が並び、末尾の統計行に送った要求の数・受け取った応答の数・届かなかった割合と、往復時間の最小・平均・最大がまとめて示される。応答が返らないのは、宛先が止まっている場合だけでなく、経路の途中の設定で ICMP の合図そのものが拒否されている場合もある(#46「administratively prohibited unreachable」の実例)。ping が確かめるのは ICMP のやり取りだけであり、宛先の特定のサービス(例えば 443 番で待つ Web サーバ)が動いているかどうかまでは分からない。ポート単位で確かめたいときは、nc -zv example.com 443 のような、宛先とポート番号を指定する別の道具を使う。

試してみよう

ping -c 3 example.com

見方: icmp_seq= と ttl= はひとまず置いて、time= に続く数字(往復時間)と、末尾の統計行の 3 つの数字(送った数・受け取った数・失われた割合)を見る。

command not found などで動かなければ、読むだけで進んでよい。
