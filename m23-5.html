第 23 章 ロードバランシング　23-5

利用者は、ロードバランサにどうたどり着くか

このページでわかること

利用者が振り分ける機械自体のアドレスをどうやって知るかを確認する。名前解決の答えそのものを使い分けて振り分けを行う方式もあることと、クラウド 3 社での呼び方の対応を確認する。

このページの目次

かけあい

ロードバランサって、いろんな機械が裏で動いてるんですよね? 利用者は、最初にどうやってそこにたどり着くんですか?

第 16 章で見た名前解決と同じです。利用者は、まず名前解決でロードバランサの IP アドレスを受け取ります。

そのアドレス宛てに送れば、あとは前のページまでの仕組み(ラウンドロビンやフローハッシュ)にお任せ、ってことですね。

そのとおりです。この名前解決の答えにも、第 16 章で見た TTL が付いています。ロードバランサでは、この秒数を短めに設定することがあります。

短くすると、何がいいんですか?

通信量の変化に応じて構成を変えたときに、利用者側の古い答えが早く入れ替わり、新しい IP アドレスにすぐ切り替えられます。

振り分けって、ロードバランサという機械だけがやるものなんですか?

実は、名前解決の答えそのものを使い分けて、振り分けを行う方式もあります。第 22 章 22-4 で見た、近くのエッジサーバのアドレスを答える方式を覚えていますか?

はい、近くの配信先を教えてくれる方式でしたよね。

同じ考え方が、自社の複数サーバへの振り分けにも使われることがあります。AWS の Amazon Route 53 には、応答する比率を決めて答えを使い分けたり、応答の速さに応じて答えを変えたりする設定があります。

DNS の応答自体で振り分けるってことですね。使えなくなった答えを外すような仕組みもあるんですか?

あります。健康な答えだけを複数返したり、使えなくなったら別の答えに切り替えたりする設定もあります。ここにも、前のページで見たヘルスチェックに近い考え方が使われています。

GCP のロードバランサも、DNS の答えを工夫するタイプなんですか?

違います。GCP のロードバランサは、1 つの Anycast の IP アドレスを窓口にする方式です。第 22 章で見た Anycast の考え方が、ここでも使われています。

じゃあ、DNS の答えを使い分ける方式と、Anycast の方式と、両方あるってことですね。

そうです。目的は同じでも、実現の仕方は事業者によって異なります。

呼び方は 3 社で違うんですか?

はい。Azure には、Traffic Manager という、DNS の応答を使って負荷分散を行うサービスがあります。

ロードバランサ自体の種類の呼び方も、3 社で違うんですか?

はい、名前も違います。表で確認しましょう。

まとめ

  • 利用者は、名前解決でロードバランサの IP アドレスを受け取ってから、そのアドレス宛てに要求を送る。
  • ロードバランサの DNS の答えにも TTL が付いており、AWS ではこの秒数を短めに設定することで、構成の変更に応じて素早く IP アドレスを切り替えられる。
  • 名前解決の答えそのものを使い分けて振り分けを行う方式もある。AWS の Amazon Route 53 には、比率や応答の速さに応じて答えを変える設定、健康な答えを複数返す設定、使えなくなったら別の答えに切り替える設定がある。
  • Azure には、DNS の応答を使って負荷分散を行う Traffic Manager というサービスがある。
  • GCP のロードバランサは、DNS の答えを使い分けるのではなく、1 つの Anycast の IP アドレスを窓口にする方式であり、第 22 章で見た Anycast の考え方の応用である。
  • クラウド 3 社は、ロードバランサ自体の種類の呼び方も異なる。

しくみの話

利用者は、名前解決でロードバランサの IP アドレスを受け取ってから、そのアドレス宛てに要求を送る(#25)。この DNS の答えにも TTL が付いており、AWS は 60 秒という短い値を使う。通信量の変化に応じて構成を変えたときに、利用者側の古い答えを早く入れ替え、新しい IP アドレスへ素早く付け替えるためである(#25)。振り分けは、ロードバランサという機械だけでなく、名前解決の答えそのものを使い分けることでも行える。AWS の Amazon Route 53 には、応答する比率を決めて答えを使い分ける設定、応答の速さに応じて答えを変える設定、使えなくなったら別の答えに切り替える設定、健康な答えを複数返す設定がある(#24)。Azure には、DNS の応答を使って負荷分散を行う Traffic Manager というサービスがある(#41)。クラウド 3 社のロードバランサの種類は、次の表のとおり対応する。

試してみよう

dig <あなたのサイト>

見方: ANSWER SECTION に並ぶ A レコードの行数を見てください。複数あれば、同じ名前に複数の宛先アドレスが対応しており、その中にロードバランサの複数の振り分け役(ノード)のアドレスが含まれていることがあります。

1 行しか無くても異常ではない(単一のアドレスの先で振り分けが行われている場合や、Anycast の方式が使われている場合がある)。command not found などで動かなければ、読むだけで進んでよい。
