第 17 章 DNS の運用と障害　17-3

名前解決で遅くなる

このページでわかること

名前解決は軽い処理だと言われるが、それでもページの表示を遅くする原因になることがある。問い合わせ先の DNS リゾルバが遠かったり、答えが DNS キャッシュに残っておらず問い合わせが何度も重なったりすると、待ち時間が積み重なる。このページでは、この遅れがどこから来るかを確認する。

このページの目次

かけあい

名前解決自体は軽い処理だって聞いたことがあるんですけど、それでもページの表示が遅くなる原因になることってあるんですか?

あります。代表的なのは、問い合わせ先の DNS リゾルバが地理的に遠い場合です。

遠いと、そんなに違うものなんですか?

第 2 章で見た往復時間(RTT)のとおり、遠い相手ほど 1 回の問い合わせに時間がかかります。

1 回の問い合わせだけじゃなくて、何度も問い合わせすることもあるんですか?

あります。答えが DNS キャッシュに残っていなければ、第 16 章で見たとおり DNS リゾルバはルートサーバ→TLD のサーバ→権威サーバの順に何度も問い合わせを重ねます。1 回 1 回に往復の時間がかかる分、遠い DNS リゾルバではこの積み重ねがより大きくなります。

なるほど、遠いこと自体と、何度も重なることの、両方が効いてくるんですね。

そのとおりです。よくある事例なんですが、利用者から遠い地域にある DNS リゾルバを使っていたために、名前解決のたびに余計な時間がかかっていた、という話があります。

なんで遠いとそんなに遅くなるんですか?

今話したとおり、DNS リゾルバとの往復に加えて、DNS キャッシュが無ければさらに何度も往復が重なるからです。

DNS キャッシュが残っていれば、この問題は起きないんですか?

DNS キャッシュに答えが残っていれば、DNS リゾルバへの 1 回の問い合わせだけで済みます。それでも、その DNS リゾルバ自体が遠ければ、その 1 回の往復には時間がかかります。

逆に、DNS キャッシュがあれば、遠くても速いってことですか?

そうです。DNS キャッシュに答えが残っている間は、DNS リゾルバへの問い合わせ自体が省略されるので、名前解決にかかる時間はほぼゼロになります。

じゃあ、いつも同じサイトを見ているだけなら、名前解決の遅さはあまり気にしなくていいんですか?

そのとおりです。問題になりやすいのは、普段使わない DNS リゾルバに切り替えたときや、初めて名前解決する名前にアクセスしたときです。

これって、DNS レコードの設定の仕方を変えれば解決するものなんですか?

いいえ、これは問い合わせ先の DNS リゾルバの位置や、DNS キャッシュの有無による問題なので、DNS レコードの設定とは別の話です。使う DNS リゾルバを選び直すことが対策になります。

実際にその時間、自分でも見れたりするんですか?

見れます。次の試してみようで確認しましょう。

まとめ

  • 名前解決がページの表示を遅くする原因には、問い合わせ先の DNS リゾルバが地理的に遠い場合と、DNS キャッシュが無く問い合わせが何度も重なる場合がある。
  • 第 2 章で見た往復時間(RTT)のとおり、遠い相手ほど 1 回の問い合わせに時間がかかる。
  • DNS キャッシュに答えが残っていなければ、DNS リゾルバはルートサーバ→TLD のサーバ→権威サーバの順に何度も問い合わせを重ね、遠い DNS リゾルバではこの積み重ねがより大きくなる。
  • 利用者から遠い地域にある DNS リゾルバを使っていたために、名前解決のたびに余計な時間がかかっていた、という事例がある。
  • DNS キャッシュに答えが残っている間は問い合わせ自体が省略されるため、いつも同じ名前にアクセスしている場合は遅れが問題になりにくい。
  • この遅れは、問い合わせ結果の Query time の行から確認できる。

しくみの話

名前解決による遅延の代表的な原因は、問い合わせ先の DNS リゾルバが地理的に遠いことである。第 2 章で見た往復時間(RTT)のとおり、遠い相手ほど 1 回の問い合わせに時間がかかる(#53「High latency」)。さらに、答えが DNS キャッシュに残っていない場合、DNS リゾルバは第 16 章で見たとおりルートサーバ→TLD のサーバ→権威サーバの順に何度も問い合わせを重ねる。1 回 1 回の往復に時間がかかる分、遠い DNS リゾルバを使っているときほど、この積み重ねは大きくなる。DNS キャッシュに答えが残っていれば、DNS リゾルバへの 1 回の問い合わせだけで済むが、その DNS リゾルバ自体が遠ければ、その 1 回の往復にも時間がかかる。名前解決にかかった時間は、問い合わせ結果の Query time の行から確認できる。

試してみよう

dig example.com

見方: 結果の末尾近くにある Query time の行の数字(ミリ秒)が、この問い合わせにかかった時間である。この数字が大きいほど、問い合わせ先が遠かったり、途中で何度も問い合わせが重なったりしたことを示す。

command not found などで動かなければ、読むだけで進んでよい。
