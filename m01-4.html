第 1 章 パケットの旅　1-4

層に分ける理由と封筒の重なり

このページでわかること

通信のしくみは、担当する範囲ごとに層(レイヤ)に分けて作られている。1 つの HTTP リクエストは、送るときに層ごとの情報が付け足されていき、受け取る側はそれを外側から順に外していく。このページでは、層がなぜ分かれているかと、その中身がどう包まれていくかを確認する。

このページの目次

かけあい

1-3 で見た、家までの機器たちって、1-1 で送った HTTP リクエストの中身を全部見てるんですか?

見ていません。家庭用ルータや経路上のルータは、宛先の IP アドレスだけを見て次に転送し、HTTP の中身まで見るのは送り先のサーバだけです。

同じ 1 つのリクエストなのに、見ている場所が機器によって違うのはなぜですか?

仕事をあらかじめ分けてあるからです。通信のしくみは役割ごとの層(レイヤ)に分けて作られていて、層ごとに担当と見る範囲が決まっています。

そういえば、IP アドレスとかポート番号とか、宛先っぽいものがいくつもありますよね。それも層が分かれているからですか?

そのとおりです。下から物理層・データリンク層・ネットワーク層・トランスポート層・アプリケーション層の 5 段に分けて見ていきましょう。

一番下から教えてください。

物理層は、0 と 1 を電気信号や電波にして運ぶ層です。その上のデータリンク層は、同じ配線の中で隣の機器を指す番号であるMAC アドレスを使って次へ渡す層です。この配線の約束事をイーサネットと呼び、詳しくは第 3 章で扱います。

1-3 で見た家庭用ルータや途中のルータは、どの層で動いているんですか?

その上のネットワーク層です。ネットワークをまたいで届ける層で、宛先は IP アドレスです。さっき言った「ルータは IP アドレスだけを見る」というのは、まさにこの層の役割です。

じゃあポート番号も、IP アドレスと同じネットワーク層の話ですか?

いいえ、違います。ポート番号はその上のトランスポート層の宛先で、端末の中のどのアプリに渡すかを決めます。ここでよく使われるのが 1-1 で見た、会話できる状態を作るTCPで、詳しくは第 13 章で扱います。

一番上がアプリケーション層ですね?

そうです。何をしてほしいかを伝える層で、URL や HTTP のやり取りがここに当たります。図にまとめると、こうなります。

上(利用者に近い)
+--------------------------------------+
アプリケーション層  [Part 5]
  役割: 何をしてほしいかを伝える
  宛先・手がかり: URL や、その先の中身
  代表例: HTTP
   |
トランスポート層  [Part 3]
  役割: どのアプリに渡すかを選ぶ
  宛先・手がかり: ポート番号
  代表例: TCP
   |
ネットワーク層  [Part 2]
  役割: ネットワークをまたいで届ける
  宛先・手がかり: IP アドレス
  代表例: IP
   |
データリンク層  [Part 1]
  役割: 同じ配線の中で次の機器へ渡す
  宛先・手がかり: MAC アドレス
  代表例: 有線の配線や無線
   |
物理層  [Part 1]
  役割: 信号にして運ぶ
  宛先・手がかり: 電気信号や電波
  代表例: ケーブルや電波
+--------------------------------------+
下(回線に近い)

層ごとに見る宛先や手がかりが違うから、宛先っぽいものがいくつも出てくる。下の 2 段は Part 1、その上は順に Part 2・Part 3・Part 5 で学ぶ。

層の名前って、実務でも教科書でも同じ呼び方なんですか?

呼び方が 2 つあります。実務でよく使うのが TCP/IP モデルという 4 層の整理、教科書でよく出てくるのが OSI 参照モデルという 7 層の整理です。今日は名前と、何層に分けるかだけ知っておけば十分で、詳しい対応表はしくみの話に置きます。

実際に HTTP リクエストを送るとき、層はどう動くんですか?

層ごとにデータの前へ、宛先などの情報を書いた部分を付け足していきます。これをヘッダと呼び、トランスポート層で TCP のヘッダ、ネットワーク層で IP のヘッダ、データリンク層でイーサネットのヘッダの順に付きます。図にすると、こうなります。

送信するとき(外側へ向けてヘッダを付け足す)

  HTTP の中身
   → [ TCP のヘッダ | HTTP の中身 ]
   → [ IP のヘッダ [ TCP のヘッダ | HTTP の中身 ] ]
   → [ イーサネットのヘッダ [ IP のヘッダ [ TCP のヘッダ | HTTP の中身 ] ] ]

受け取るとき(外側から順にヘッダを外す)

  [ イーサネットのヘッダ [ IP のヘッダ [ TCP のヘッダ [ HTTP の中身 ] ] ] ]
   → イーサネットのヘッダを外す
   → IP のヘッダを外す
   → TCP のヘッダを外す
   → HTTP の中身が残る

送信するときはトランスポート層・ネットワーク層・データリンク層の順にヘッダが付き足され、受け取るときは外側から順に外されて、最後に HTTP の中身だけが残る。

封筒に入れるみたいですね。

近いです。手紙を封筒に入れ、さらに別の封筒に入れるイメージで簡略化でき、正式にはこの処理をカプセル化と呼びます。HTTP や TCP、IP のような共通の約束事はプロトコルと呼びます。

IP の封筒に入ったかたまりにも、名前があるんですか?

あります。パケットと呼びます。途中のルータはこの封筒を全部開けず、自分の層である IP ヘッダの宛先だけを見て転送します。

見る場所を層ごとに決めてあるから、そんなことができるんですね。下の層を無線から有線に変えても、上の TCP や HTTP はそのままでいいってことですか?

そのとおりです。下の層(回線の種類)を差し替えても、上の層(TCP や HTTP)を作り直さなくてよいのが、層を分ける一番の理由です。

まとめ

  • 通信のしくみは、下から物理層・データリンク層・ネットワーク層・トランスポート層・アプリケーション層の 5 つの層(レイヤ)に分かれており、層ごとに見る宛先や手がかり(電気信号・MAC アドレス・IP アドレス・ポート番号・URL)が違う。
  • 送信するときは、上位層のデータに下位層のヘッダを順に付け足していく(トランスポート層 → ネットワーク層 → データリンク層)。これをカプセル化と呼び、受け取る側はその逆に外側から順にヘッダを外していく。
  • IP の封筒に入った状態のひとかたまりをパケットと呼び、途中のルータは自分の層である IP ヘッダの宛先だけを見て転送する。
  • 層を分けているおかげで、下の層(回線の種類など)を変えても、上の層(TCP や HTTP など)を作り直す必要がない。

しくみの話

かけあいで手紙を何重にも封筒に入れることにたとえたとおり、カプセル化は下位層に進むごとに前の層のデータを丸ごと包み込み、ヘッダを付け足す処理である。OSI 参照モデルの 7 層は、アプリケーション層・プレゼンテーション層・セッション層をまとめて TCP/IP モデルのアプリケーション層に、ネットワーク層をインターネット層に、データリンク層・物理層をまとめてネットワークインターフェース層に対応づけられる(#73)。この講座で扱う 5 段は、次の表のとおり Part と対応する。

OSI 参照モデル(7 層)TCP/IP モデル(4 層)この講座の 5 段
アプリケーション層・プレゼンテーション層・セッション層アプリケーション層アプリケーション層(Part 5)
トランスポート層トランスポート層トランスポート層(Part 3)
ネットワーク層インターネット層ネットワーク層(Part 2)
データリンク層・物理層ネットワークインターフェース層データリンク層・物理層(Part 1)

この対応を丸暗記する必要はなく、「今どの層の話をしているか」を都度確認する習慣が、後の章の理解を助ける。
