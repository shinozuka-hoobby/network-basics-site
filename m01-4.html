第 1 章 パケットの旅　1-4

層に分ける理由と、どの機器にも積まれている 5 つの段

このページでわかること

通信のしくみは、担当する仕事ごとに層(レイヤ)に分けて作られている。この層は通信の道筋に順番に並んでいるものではなく、自分の PC にも、途中の機器にも、相手のサーバにも、同じ 5 段が積まれている。このページでは、段ごとの担当と、機器ごとに何段目まで使うかを確認する。

このページの目次

かけあい

1-3 で見た家までの機器たちって、1-1 で送った HTTP リクエストの中身を全部見てるんですか?

見ていません。家庭用ルータや経路上のルータは、宛先の IP アドレスだけを見て次へ送ります。HTTP の中身まで見るのは、送り先のサーバだけです。

同じ 1 つのリクエストなのに、機器によって見ている場所が違うのはなぜですか?

仕事をあらかじめ 5 つに分けてあるからです。この分け方を層(レイヤ)と呼び、層ごとに、何を担当し、何を宛先として見るかが決まっています。

その層って、どこにあるものなんですか? 1-3 の図みたいに、道の途中に順番に並んでいるイメージですか?

そこが一番つまずきやすいところです。層は道の途中に並んでいるのではなく、あなたの PC の中にも、途中のルータの中にも、相手のサーバの中にも、同じ 5 段が積まれています。棚の段のようなものだと考えてください。

全部の機器が同じ 5 段を持っているなら、機器ごとの違いはどこにあるんですか?

何段目まで使うか、だけです。それを見るために、まず 5 段の中身を下から確認しましょう。一番下の 1 段目の物理層は、0 と 1 を電気信号や電波にして運ぶ段です。

その上の 2 段目がデータリンク層で、同じ配線でつながった隣の機器へ渡す段です。宛先には、機器のネットワーク部品ごとに付いた番号であるMAC アドレスを使い、この配線の約束事をイーサネットと呼びます。詳しくは第 3 章で扱います。

隣の機器へ渡すだけなんですね。遠くのサーバまで届けるのは、どの段ですか?

その上の 3 段目のネットワーク層です。ネットワークをまたいで最終的な届け先まで運ぶ段で、宛先は IP アドレスです。「ルータは IP アドレスだけを見る」と言ったのは、ルータが使うのがこの段までだからです。

じゃあポート番号も、IP アドレスと同じネットワーク層の話ですか?

いいえ、別の段です。ポート番号は 4 段目のトランスポート層の宛先で、届いた先の機器の中のどのアプリに渡すかを決めます。ここで使われるのが 1-1 で出てきた、会話できる状態を作るTCPで、詳しくは第 13 章で扱います。

一番上の 5 段目が、HTTP のいるアプリケーション層ですね?

そうです。何をしてほしいかを伝える段で、URL や HTTP のやり取りがここに当たります。5 段を図にまとめると、こうなります。

上(利用者に近い)
+--------------------------------------+
5 段目 アプリケーション層  [Part 5]
  役割: 何をしてほしいかを伝える
  宛先・手がかり: URL や、その先の中身
  代表例: HTTP
   |
4 段目 トランスポート層  [Part 3]
  役割: 届いた機器の中のどのアプリに渡すか
  宛先・手がかり: ポート番号
  代表例: TCP
   |
3 段目 ネットワーク層  [Part 2]
  役割: ネットワークをまたいで最終的な
        届け先まで運ぶ
  宛先・手がかり: IP アドレス
  代表例: IP
   |
2 段目 データリンク層  [Part 1]
  役割: 同じ配線の中で、隣の機器へ渡す
  宛先・手がかり: MAC アドレス
  代表例: 有線の配線や無線
   |
1 段目 物理層  [Part 1]
  役割: 0 と 1 を信号にして運ぶ
  宛先・手がかり: 電気信号や電波
  代表例: ケーブルや電波
+--------------------------------------+
下(回線に近い)

通信の仕事は、下から 1 段目の物理層から 5 段目のアプリケーション層まで、役割ごとの 5 つの段に分かれている。段ごとに見る宛先や手がかりが違うから、宛先っぽいものがいくつも出てくる。

この 5 段が PC にもルータにもサーバにも入っていて、違いは何段目まで使うか、でしたよね。それも図で見たいです。

こうなります。

 自分の PC   途中のルータ  相手のサーバ
 +---+                     +---+
 | 5 |                     | 5 |
 | 4 |       +---+         | 4 |
 | 3 |       | 3 |         | 3 |
 | 2 |       | 2 |         | 2 |
 | 1 |       | 1 |         | 1 |
 +---+       +---+         +---+
   |           |             |
   +---配線----+----配線-----+

 5 = アプリケーション層
 4 = トランスポート層
 3 = ネットワーク層
 2 = データリンク層
 1 = 物理層

 リクエストは PC の 5 段を上から下へ降り、
 配線を渡ってルータの 1 → 3 段目まで上がり、
 また 1 段目まで降りて次の配線へ出て、
 サーバで 1 → 5 段目まで上がって
 HTTP の中身になる。

5 つの段は、どの機器の中にも積まれている。機器ごとに違うのは何段目まで使うかで、PC とサーバは 5 段すべて、途中のルータは下から 3 段目のネットワーク層まで。

PC とサーバは 5 段全部で、途中のルータは下の 3 段までなんですね。だからルータは IP アドレスまでしか見ない、と。

そのとおりです。どの機器も一番下の段から受け取り、必要な段まで上がって仕事をし、また下の段へ降りて次の機器へ送り出します。ルータは 3 段目で次の送り先を決めたら 1 段目まで降りて送り出すので、ルータが何台あっても同じことの繰り返しです。

層の名前って、実務でも教科書でも同じ呼び方なんですか?

呼び方が 2 つあります。実務でよく使うのが TCP/IP モデルという 4 層の整理、教科書でよく出てくるのが OSI 参照モデルという 7 層の整理です。今日は名前と層の数だけで十分で、5 段との対応表はしくみの話に置きます。

仕事を段に分けておくと、何がうれしいんですか?

下の段を差し替えても、上の段を作り直さなくてよいことです。たとえば無線を有線に変えても、上の TCP や HTTP はそのまま使えます。リクエストが実際にこの 5 段をどう通っていくかは、次の 1-5 で封筒の形で追いかけましょう。

まとめ

  • 通信のしくみは、下から物理層・データリンク層・ネットワーク層・トランスポート層・アプリケーション層の 5 つの層(レイヤ)に分かれており、段ごとに見る宛先や手がかりが違う。
  • 層は通信の道筋に順番に並んでいるのではなく、PC・ルータ・サーバのどの機器にも同じ 5 段が積まれている。機器ごとに違うのは何段目まで使うかだけ。
  • PC とサーバは 5 段すべてを使い、途中のルータは下から 3 段目のネットワーク層までを使う。だからルータは宛先の IP アドレスまでしか見ない。
  • 層の整理には TCP/IP モデル(4 層)と OSI 参照モデル(7 層)がある。この講座では 5 段で扱う。
  • 層を分けているおかげで、下の段(回線の種類など)を変えても、上の段(TCP や HTTP など)を作り直す必要がない。

しくみの話

かけあいで棚の段にたとえたとおり、層は通信の仕事を役割ごとに分けた整理であり、PC・ルータ・サーバのどの機器にも、下の段から順に同じ段が積まれている。機器ごとの違いは使う段の高さで、PC やサーバは 5 段すべて、途中のルータはネットワーク層までを使う(#4)。OSI 参照モデルの 7 層は、アプリケーション層・プレゼンテーション層・セッション層をまとめて TCP/IP モデルのアプリケーション層に、ネットワーク層をインターネット層に、データリンク層・物理層をまとめてネットワークインターフェース層に対応づけられる(#73)。対応は次の表のとおり。

OSI 参照モデル(7 層)TCP/IP モデル(4 層)この講座の 5 段
アプリケーション層・プレゼンテーション層・セッション層アプリケーション層5 段目 アプリケーション層(Part 5)
トランスポート層トランスポート層4 段目 トランスポート層(Part 3)
ネットワーク層インターネット層3 段目 ネットワーク層(Part 2)
データリンク層・物理層ネットワークインターフェース層2 段目 データリンク層・1 段目 物理層(Part 1)

この対応を丸暗記する必要はなく、「今どの機器の、何段目の話か」を確かめる習慣が後の章の理解を助ける。
