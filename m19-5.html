第 19 章 HTTPS を運用する　19-5

暗号を解く場所を選ぶ

このページでわかること

TLS の暗号を解く役目は、必ずしも自分のサーバが受け持つとは限らない。手前の機械が代わりに受け持つと、その先の通信や身分証の置き場所が変わる。このページでは、この役目の分担と、その影響を確認する。

このページの目次

かけあい

この章では、身分証の取得や更新、失効の話をしてきましたけど、その身分証って、いつも自分のサーバに置いてあるものなんですか?

そうとは限りません。TLS の暗号を解く役目を、どの機械が受け持つかをTLS 終端と呼び、これにはいくつかの選択肢があります。

解く役目、ですか? どこでもいいってことですか?

1 つ目は自分のサーバです。第 18 章で見た TLS ハンドシェイクの相手が、そのまま自分のサーバになります。

他にも選択肢があるんですか?

あります。手前にロードバランサ(同じ役目を持つ複数の Web サーバに、届いたリクエストを振り分ける機械)を置いて、そこで解く方法です。詳しくは第 23 章で扱います。

もう 1 つは何ですか?

利用者の近くにある配信専用の機械、CDNで解く方法です。詳しくは第 22 章で扱います。

自分のサーバ以外で解くと、何が変わるんですか?

手前で暗号を解くと、そこから先のサーバへの通信は、暗号化されないまま転送されることがあります。

先輩から、ロードバランサで終端していたら、サーバ側のアプリが自分は http で受けていると勘違いしていた、という話を聞いたことがあります。

手前で暗号を解くと、サーバに届くのは解いた後の通信です。だからサーバ側の仕組みは、利用者との間が https だったかどうかを、自分では知りようがありません。何も伝えてもらわなければ、http で受けたものとして扱ってしまいます。

自分のサーバで解く場合と、手前で解く場合、どっちがいいんですか?

一概には言えません。運用の手間や、証明書の管理のしやすさなど、いくつかの観点で選びます。

身分証は、どこに置くことになるんですか?

暗号を解く役目を受け持つ機械に置くことになります。自分のサーバで解くなら自分のサーバに、手前で解くなら手前の機械に置きます。

CDN で解く場合も、身分証はそこに置くってことですよね?

そうです。配信専用の機械が、利用者との間の暗号化を代わりに引き受けるので、そのための身分証もそちら側に用意されます。

置き場所が変わると、更新の手間も変わりそうですね。

そのとおりです。手前でまとめて解いていれば、更新もそこでまとめて行えます。

終端する場所は、あとから変更できるものなんですか?

できます。ただし、身分証の置き場所や設定を移す作業が必要になります。

終端する場所によって、いろいろ変わるんですね。

そのとおりです。この続きは、Web を届ける仕組みを扱う次の Part で見ていきましょう。

まとめ

  • TLS の暗号を解く役目(TLS 終端)は、自分のサーバが受け持つ場合と、手前のロードバランサや CDN が代わりに受け持つ場合とがある。
  • 手前で暗号を解くと、そこから先のサーバへの通信は、暗号化されないまま転送されることがある。
  • 手前で終端していると、サーバ側の仕組みは利用者との間が https だったかどうかを自分では知りようがなく、何も伝えてもらわなければ http で受けたものとして扱ってしまうことがある。
  • 身分証は、暗号を解く役目を受け持つ機械に置かれる。終端する場所が変われば、更新の手間も変わる。

しくみの話

TLS の暗号を解く(元の中身に戻す)役目を、どの機械が受け持つかを TLS 終端と呼ぶ。自分のサーバが受け持つ場合、TLS ハンドシェイクの相手はそのまま自分のサーバになる(#55)。手前のロードバランサが受け持つ場合、通信はロードバランサの層で終端されたあとバックエンドへ転送され(#31)、その転送先ではプロトコルとして http と https のどちらも選べる(#25)。転送先が http を選んでいれば、そこから先の通信は暗号化されないまま送られる。利用者の近くにある配信専用の機械(CDN)が受け持つ場合も同様で、安全な通信を配信するための身分証は、その機械側に用意される(#62)。身分証は、暗号を解く役目を受け持つ機械に置かれ、終端する場所が変われば、身分証の置き場所や更新の手間も変わる。自分のサーバで解くか、手前の機械で解くかは、運用の手間や証明書の管理のしやすさなど、複数の観点から選ばれ、この選択は身分証をどこで更新するかという運用にも直結する。手前でまとめて終端していれば、複数台のサーバへ配る身分証を 1 か所にまとめて置け、更新の作業もそこに集約できる。終端する場所は、あとから変更することもできるが、そのときは身分証の置き場所や設定を移す作業が必要になる。

試してみよう

curl -sI https://<あなたのサイト>

見方: 応答の中の server という行を見てください。自分のサーバの名前ではなく、配信事業者の名前が書かれていれば、その事業者側で暗号を解いている手がかりになります。

server という行自体が無いサーバもあります。command not found などで動かなければ、読むだけで進んでよい。
