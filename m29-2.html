第 29 章 クラウド上の経路診断　29-2

3 社の診断ツールを比べる

このページでわかること

AWS・GCP・Azure にはそれぞれ、設定から届くかどうかを言い当てる機能がある。ただし、実際にパケットを送る機能まで持つかどうかは、3 社で違う。このページでは、3 社の機能を並べて、その違いを確認する。

このページの目次

かけあい

AWS 以外のクラウドにも、同じような診断機能ってあるんですか?

あります。GCP には Connectivity Tests、Azure には Network Watcher という名前の機能があります。

どれも同じ仕組みなんですか?

近いですが、少し違います。GCP の Connectivity Tests は、AWS と同じように設定を読み取って経路をシミュレートします。ただ、一部の場合には確認用のパケットを実際に送って、届いた割合まで測ります。

え、じゃあ AWS の Reachability Analyzer より、確かめられることが多いんですね。

一長一短です。到達した割合が 95% 以上なら「到達可能」、0 なら「到達不能」、その間なら「部分的に到達可能」と 3 段階で判定します。

Azure はどうなんですか?

Azure は、Network Watcher という機能の中に、役割の違う複数の道具が用意されています。IP flow verify は、AWS の Reachability Analyzer に近く、仮想マシンに適用された設定を読み取って、通信が許可されるか拒否されるかと、その根拠になった規則の名前を返します。

実際に送る方の道具もあるんですか?

あります。Connection troubleshoot です。実際に確認用のパケットを送り、届いたかどうかと、経由した機器ごとの情報を返します。

じゃあ Azure は、設定を読む道具と、実際に送る道具の、両方を持ってるんですね。

そのとおりです。GCP の Connectivity Tests は 1 つの機能の中に両方の性質を持ち、Azure は役割ごとに別の道具に分かれている、という違いがあります。

Connection troubleshoot は、具体的にどんな問題を見つけてくれるんですか?

サーバの CPU 使用率が高いこと、名前解決に失敗していること、ルートの設定に誤りがあることなど、複数の種類の問題を見分けてくれます。

実際に送る道具があれば、それだけで確実に分かりそうですね。

そうとも言い切れません。設定の分析では「届くはず」と出ても、実際には機械の不調などで繋がらないことがある、という報告もあります。

推論だけでも、実際に送る道具だけでも、足りないことがあるんですね。

そのとおりです。次のページでは、推論とは別に、実際に何が起きたかを記録しておく仕組みを見ていきましょう。

まとめ

  • AWS の Reachability Analyzer は設定を読み取るだけで、実際にパケットを送る機能を持たない。
  • GCP の Connectivity Tests は、設定を読み取る解析と、確認用のパケットを実際に送って届いた割合を測る分析の両方を行う。到達した割合が 95% 以上なら到達可能、0 なら到達不能、その間なら部分的に到達可能と判定する。
  • Azure の Network Watcher は役割ごとに道具が分かれており、IP flow verify は設定を読み取って許可・拒否と根拠の規則を示し、Connection troubleshoot は実際にパケットを送って到達したかどうかと経由した機器ごとの情報を示す。
  • 設定の分析で「届くはず」と判定されても、機械自体の不調など設定の外側の理由で、実際には繋がらないことがある。

しくみの話

AWS の Reachability Analyzer、GCP の Connectivity Tests、Azure の IP flow verify・Connection troubleshoot を比べると、次のようになる(#27、#115、#121、#122)。

項目AWSGCPAzure
設定を読み取って判定する機能Reachability AnalyzerConnectivity TestsIP flow verify
実際にパケットを送って確かめる機能—Connectivity Tests(一部の場合)Connection troubleshoot
届かない場合に分かること止めている設定到達した割合経由した機器ごとの問題

GCP の資料には、設定の分析結果が「届くはず」でも、実際には繋がらない場合があるという報告がある(#34)。Azure の Connection troubleshoot は、サーバの CPU 使用率が高いこと、DNS の名前解決に失敗していること、ルートの設定に誤りがあることなど、複数の種類の問題を見分けて知らせる(#122)。
