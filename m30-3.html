何を減らすと、速くなるのか

このページでわかること

これまでの章で見た高速化の工夫は、大きく 3 つの方向のどれかに当てはまる。1 往復にかかる時間を短くする方向、往復そのものの回数を減らす方向、そして同時に運べる量を増やす方向である。このページでは、これまでの章で見た仕組みを、この 3 つの方向で整理し直す。

かけあい

第 22 章の最後で、CDN や HTTP/2、TLS 1.3 が性能にどう効くかは、この章でまとめるって言ってましたよね。

そうです。ここまで見てきた工夫は、大きく 3 つの方向のどれかに当てはまります。

往復そのものの回数を減らす方向、1 往復にかかる時間を短くする方向、そして同時に運べる量を増やす方向です。

CDN はどれに当たるんですか。

1 往復の時間を短くする方向です。近いエッジサーバから返すことで、それぞれの往復にかかる時間そのものが短くなるんでした。

具体的には、どれくらい違うんでしたっけ。

第 22 章 22-5 で見た例では、遠いオリジンサーバへ直接アクセスするとおよそ 3000 ミリ秒、近いエッジサーバの控えから受け取るとおよそ 1100 ミリ秒でした。

HTTP/2 はどうですか。

同時に運べる量を増やす方向です。1 本の接続の中に独立した複数の流れ(ストリーム)を持てるので、1 つの遅れが他を止めません。

TLS 1.3 は?

往復の回数を減らす方向です。ハンドシェイクを 1 往復に短縮していて、以前に接続したことがある相手となら、次はその 1 往復すら省けます。

HTTP/3、つまり QUIC はどうなんですか。

複数の方向にまたがります。接続と TLS の手続きをまとめて往復を減らしつつ、TCP 層で起きる詰まりも無くします。第 21 章 21-3 で見たとおり、電波の状態が悪くパケットが失われやすい環境ほど、この工夫の効果が大きくなります。

詰まりを無くすっていうのは、同時に運べる量を増やす方向と同じ意味ですか。

近い意味です。1 つのパケットの損失が全部の流れを止めてしまう問題を無くすことで、複数の流れを本当の意味で同時に運べるようになります。

TLS 1.3 や 0-RTT の効果は、相手によって違うんですか。

そうです。第 15 章 15-3 で見たとおり、往復を 1 回減らす効果は、相手までの往復時間が長いほど大きくなります。

これまでバラバラに見てきた工夫が、こうして並べると整理できますね。

表を見ると、CDN だけが毎回の往復の時間を短くする方向なんですね。

まとめ

  • これまでの章で見た高速化の工夫は、往復の回数を減らす・1 往復にかかる時間を短くする・同時に運べる量を増やす、という 3 つの方向のどれかに当てはまる。
  • CDN は、近いエッジサーバから返すことで、1 往復にかかる時間そのものを短くする。
  • HTTP/2 の多重化は、1 本の接続の中に独立した複数の流れを持たせることで、同時に運べる量を増やす。
  • TLS 1.3 は、ハンドシェイクを 1 往復に短縮し、0-RTT を使えば再接続の往復さえ省く、往復の回数を減らす工夫である。
  • HTTP/3(QUIC)は、接続と TLS の手続きをまとめて往復を減らしつつ、TCP 層の詰まりも無くすため、複数の方向にまたがる。電波の状態が悪くパケットが失われやすい環境ほど、この工夫の効果が大きい。
  • 目の前の遅さが、往復の回数・1 往復の時間・同時に運べる量のどれで効いているかを見分けることが、次のページで測る際の手がかりになる。

しくみの話

CDN・HTTP/2・TLS 1.3・HTTP/3 の工夫を、主に効く方向で整理すると次のとおりになる。

技術主に効く方向理由(要約)出典
CDN1 往復を短くする近いエッジサーバから返す#58
HTTP/2同時に運ぶ量を増やす複数の流れを 1 本の接続に乗せる#56・#20
TLS 1.3往復を減らすハンドシェイクを 1 往復、0-RTT なら 0 往復#55・#57
HTTP/3往復を減らす、同時に運ぶ量を増やす接続と TLS をまとめ、詰まりも無くす#57・#64・#20

CDN は通信の手続き自体は変えず距離を縮めることで効果を出し、残りの 3 つは通信の手続き自体を作り直すことで効果を出している。往復を減らすか、1 往復を短くするか、同時に運べる量を増やすか、それぞれの技術がどこを狙っているかで整理すると分かりやすい。

試してみよう

curl -sv https://example.com -o /dev/null

見方: 出力の中で、TLS のバージョンを示す行(TLSv1.3 という表記を含む行)を探す。この行があれば、この接続は TLS 1.3 を使っており、表でいう「往復を減らす」技術が働いている。

HTTP の版を示す行(ALPN: server accepted h2 に類する行)も、同じ出力の中にある。command not found などで動かなければ、読むだけで進んでよい。
