第 19 章 HTTPS を運用する　19-4

HTTPS のページに http の部品が混ざる

このページでわかること

ページ全体を https にしても、中の画像やスクリプトが http のままだと、そこだけ守られないことがある。このページでは、この現象と、ブラウザの反応を確認する。

このページの目次

かけあい

ページ全体を https にすれば、もう安心なんですよね?

ページ本体は安心です。ただ、中の画像やスクリプトまでは別です。

え、中身も一緒に暗号化されるんじゃないんですか?

ページの中で http のまま呼び出している画像やスクリプトがあると、その部分だけは暗号化されずに送られます。

それの何が困るんですか?

その部分だけ、途中で書き換えられたり中身を見られたりする隙が残ります。だからブラウザは読み込みを止めたり、警告を出したりします。これを混在コンテンツと呼びます。

どうやって気づくんですか?

ブラウザが警告を表示したり、鍵のマークの見た目が変わったりすることで気づけます。

個人開発で、https 化したのに画像が表示されなかったり、警告が出たりしたことがあります。

まさに、http のまま画像を呼び出していたための混在コンテンツですね。呼び出し先を https に直せば直ります。

スクリプトでも同じことが起きるんですか?

はい。画像に限らず、http のまま呼び出している部品であれば、同じことが起きます。

一部だけ古いまま忘れてる、みたいなことも起きそうですね。

よくあります。サイト全体を https にしたばかりの時期は、こうした部品の直し忘れがそのまま残っていることがあります。

表示は特に変じゃないのに、実は混在コンテンツになってる、みたいなこともあるんですか?

あります。画像が小さかったり目立たなかったりすると、見た目だけでは気づきにくいことがあります。

じゃあ、どうやって確認するのがいいんですか?

ブラウザの開発者ツールを開くと、どの部品が http のまま読み込まれているか、詳しく確認できます。

これは、https に切り替えた直後だけの問題なんですか?

切り替え直後に多いですが、後から追加した部品が http のままだった、ということもあります。

外部のサービスから取り込んでいる部品も対象になるんですか?

なります。自分で用意した部品だけでなく、外部から取り込んでいる部品も、呼び出し先が http のままなら同じことが起きます。

ページを https にするときは、部品も全部確認しないといけないんですね。

そのとおりです。次のページでは、この暗号を解く役目を誰が受け持つかを見ていきましょう。

まとめ

  • ページ本体を https にしても、中の画像やスクリプトが http のまま呼び出されていると、その部分だけは暗号化されずに送られる。
  • これを混在コンテンツと呼び、ブラウザは警告を出したり、その部品の読み込みを止めたりする。
  • 混在コンテンツは、ブラウザの警告や見た目の変化から気づけることが多いが、部品が目立たない場合は見た目だけでは気づきにくいこともある。
  • ブラウザの開発者ツールを開くと、どの部品が http のまま読み込まれているかを詳しく確認できる。
  • https 化したのに画像が表示されない、警告が出るといった現象は、http のまま部品を呼び出していることが原因であることが多い。切り替え直後だけでなく、後から追加した部品が原因になることもある。
  • 画像に限らず、スクリプトなど呼び出す部品すべてが対象になる。

しくみの話

ページ本体を https にしても、その中で http のまま呼び出している画像やスクリプトがあると、その部分だけは暗号化されずに送られる。これを混在コンテンツと呼ぶ。その部分だけ、途中で書き換えられたり中身を見られたりする隙が残るため、ブラウザはその部品の読み込みを止めたり、警告を出したりする。画像に限らず、http のまま呼び出している部品であれば、スクリプトなど種類を問わず同じことが起きる。https 化したのに画像が表示されない、警告が出るといった現象は、こうした部品の呼び出し先を http のまま直し忘れていることが原因であることが多い。呼び出し先を https に直せば、この現象は解消する。混在コンテンツは、部品が小さかったり目立たなかったりすると、見た目だけでは気づきにくいことがある。ブラウザの開発者ツールを使うと、どの部品が http のまま読み込まれているかを詳しく確認できる。https 化した直後だけでなく、後から追加した部品が原因になることもある。混在コンテンツは、Web サイトを https に切り替える作業でよく起きる典型的な見落としであり、自分で用意した部品か外部から取り込んだ部品かを問わず、呼び出し先を https に揃えることが根本的な対策になる。
