このページでわかること

dig の実行結果は、これまでの章で断片的に見てきたが、実は尋ねた内容の区画、答えの区画などに、あらかじめ決まった形で分かれている。答えの区画には、これまでに見た DNS レコードと DNS の TTL が並ぶ。このページでは、この区画の全体像と、結果に添えられる短い言葉の読み方を確認する。

このページの目次

かけあい

これまでの章で dig を何回も実行してきましたけど、結果に区画がいくつもあって、正直まだ全体像が分かってないんです。

第 16 章 16-5 で少し触れましたが、今日は結果の区画を整理しましょう。dig の結果は、尋ねた内容の区画と、答えの区画のほかに、権威サーバの情報を載せる区画、追加の情報を載せる区画の、決まった区画に分かれています。

区画の分け方って、dig が勝手に決めてるんですか。

いいえ。名前解決の問い合わせと答えのやり取り自体の決まりごとで、その決まりを dig がそのまま表示しています。

権威サーバの情報を載せる区画って、いつ使われるんですか。

答えの区画だけでは足りないときに、参考として権威サーバの名前などが載ります。答えがすでに十分な問い合わせでは、空になることもあります。

追加の情報を載せる区画には、何が入るんですか。

答えに直接は当たらないけれど、参考になる情報です。例えば、権威サーバの名前だけでなく、その権威サーバ自身の住所が載ることがあります。

第 17 章で見た NOERROR とか NXDOMAIN は、どこに出るんでしたっけ。

status: に続けて表示されます。

dig コマンド自体が失敗したときと、NXDOMAIN が返ってきたときって、見分けられるんですか。

別物です。NXDOMAIN は、問い合わせ自体はきちんと処理された上で、その名前が無いという答えが返ってきた状態です。dig コマンド自体が動かなかった場合とは違います。

flags: っていう行もありましたよね。

そこには qr や rd といった短い文字が並びます。問い合わせなのか答えなのか、答えを探しに行くよう頼んだかどうかなどを、この短い文字で示しています。

答えの区画には、何が並ぶんですか。

第 16 章で見た DNS レコードと、DNS の TTL が並びます。これまでの章で見てきた内容が、実はこの区画にまとまっていたんです。

Query time っていう行も見た覚えがあります。

結果の末尾近くにある行で、問い合わせにかかった時間を示します。SERVER という行には、どこに問い合わせに行ったかも表示されます。

毎回この長い結果を全部見るのは大変そうですね。

答えの区画だけを短く表示する、簡潔な聞き方も用意されています。

dig にそういう聞き方もあったんですね。

はい。知りたい内容によって使い分けてください。次のページでは、curl の出力を記号で見分ける方法を見ていきましょう。

まとめ

  • dig の結果は、尋ねた内容・答え・権威サーバの情報・追加情報という、決まった区画に分かれて表示される。
  • flags: には qr・rd などの短い文字が、status: には NOERROR・NXDOMAIN・SERVFAIL などの言葉が表示される。
  • 答えの区画には、これまでに見た DNS レコードと DNS の TTL が並ぶ。
  • Query time は問い合わせにかかった時間、SERVER はどこに問い合わせたかを示す。
  • 答えの区画だけを短く表示する聞き方もある。

しくみの話

dig の結果は、尋ねた内容(QUESTION)、答え(ANSWER)、権威サーバの情報(AUTHORITY)、追加の情報(ADDITIONAL)という決まった区画に分かれて表示される(#83 §4.1)。この区画分けは、名前解決の問い合わせと答えのやり取り自体の形式として定められている(#83)。追加の情報の区画には、答えに直接は当たらないが参考になる情報(権威サーバ自身の住所など)が載ることがある(#83)。dig コマンド自体の成否と、答えが NOERROR か NXDOMAIN かは別物である。NXDOMAIN は、問い合わせが処理された上で「その名前は無い」という答えが返ってきた状態であり、dig コマンド自体が動かなかった場合とは区別される(#105)。flags: に続く qr・rd などの文字と、status: に続く言葉(NOERROR・NXDOMAIN・SERVFAIL など)も、この形式の一部である(#83 §4.1.1)。答えの区画には、第 16 章で見た DNS レコードと DNS の TTL が並ぶ。結果の末尾近くには、問い合わせにかかった時間(Query time)と、問い合わせ先(SERVER)が表示される。答えの区画だけを短く表示する、dig +short という聞き方も用意されている(#105)。

試してみよう

dig example.com

見方: 結果が複数の区画に分かれていること、flags: に続く文字と status: に続く言葉、Query time と SERVER の行を確認する。

command not found などで動かなければ、読むだけで進んでよい。
