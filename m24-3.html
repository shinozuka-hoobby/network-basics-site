第 24 章 クラウドの仮想ネットワーク（VPC）　24-3

許可を覚えているか、そのつど確かめるか

このページでわかること

クラウドのサーバへの通信を許可・拒否する設定には、サーバ 1 台ずつにかけるものと、区画の境目にかけるものの、2 種類がある。この 2 つは、対象にする範囲だけでなく、戻りの通信の扱いも違う。このページでは、その違いを確認する。

このページの目次

かけあい

VPC の中のサーバに、通信を許可する設定をしたことがあるんですけど、あれは何をしてたんですか?

それがセキュリティグループです。サーバ 1 台ずつに対して、どの通信を許してよいかを決める仕組みです。

サーバの外側、サブネットの境目にも、似たような設定ってあるんですか?

あります。NACL(ネットワーク ACL)と呼ばれ、サブネットの境目で通信を許可・拒否します。

セキュリティグループと NACL、対象にする範囲が違うんですね。

そのとおりです。セキュリティグループはサーバ 1 台ずつ、NACL はサブネットの境目全体にかかります。

範囲以外にも、違いってあるんですか?

あります。戻りの通信の扱いも違います。

戻りの通信、というと?

セキュリティグループは、一度許可した通信の戻りを自動で通します。これをステートフルと呼びます。

NACL は違うんですか?

はい。NACL は、以前に送った・受け取った通信の情報を覚えていないため、行きと帰りをそれぞれ許可しないと通りません。これをステートレスと呼びます。

先輩から聞いたんですけど、NACL で外から来る 443 番宛ての通信を許可したのに、外から要求は届くのに応答が返らなかったことがあるらしいです。

NACL はステートレスなので、行きの通信を許可しても、戻りの通信は別に許可しないと通りません。応答が返らなかったのは、戻りの通信を許可するルールが無かったからだと思います。

戻りの通信って、具体的にはどのポート宛てになるんですか?

サーバからの応答は、要求を送ってきた側の一時的なポート宛てになります。第 12 章で見た、通信のたびに割り当てられる番号です。

なるほど、セキュリティグループだったら、これは自動で通っちゃうってことですね。

そのとおりです。だから、セキュリティグループだけで運用していると、この違いに気づきにくいのです。

ルールの調べ方も、セキュリティグループと NACL で違うんですか?

はい。セキュリティグループは、すべてのルールを確認してから通信を許可するかどうかを決めます。NACL は、番号の小さい順にルールを確認していき、最初に一致したルールをそのまま適用します。

セキュリティグループも NACL も、決めた条件に合わない通信を止める、っていう意味では同じ種類の仕組みってことですか?

そうです。どちらも、決めた条件に合わない通信を、機械やネットワークの手前で止める仕組みです。

その仕組み全体にも、呼び方があるんですか?

あります。ファイアウォールと呼びます。詳しくは第 26 章で扱います。

まとめ

  • セキュリティグループは、サーバ 1 台ずつに対して、どの通信を許可するかを決める仕組みである。
  • NACL は、サブネットの境目で通信を許可・拒否する設定である。セキュリティグループとは、対象にする範囲(サーバ 1 台ずつか、境目全体か)が違う。
  • セキュリティグループは、一度許可した通信の戻りを自動的に通す(ステートフル)。NACL は、戻りの通信も別に許可する必要がある(ステートレス)。
  • セキュリティグループも NACL も、決めた条件に合わない通信を止める仕組みという意味で、ファイアウォールの一種である。

しくみの話

セキュリティグループは、クラウドのサーバに対して、どの通信を許してよいかを決める仕組みで、サーバ(インスタンス)単位に適用される(#97)。NACL(ネットワーク ACL)は、サブネットの境目で通信を許可・拒否する設定で、そのサブネットに属するすべてのサーバに一律に適用される(#96、#97)。両者は戻りの通信の扱いも異なる。セキュリティグループは、一度許可した通信の戻りを自動的に許可する(ステートフル)(#95)。NACL は、以前に送った・受け取った通信の情報を保存しないため、行きの通信を許可しても戻りの通信は別に許可しなければならない(ステートレス)(#96)。この対象範囲と戻りの通信の扱いの違いから、セキュリティグループを主な手段として使い、必要に応じて NACL を追加の防御層として使うという使い分けができる(#97)。ルールの調べ方にも違いがあり、セキュリティグループはすべてのルールを確認してから許可するかどうかを決めるのに対し、NACL は 1 から 32766 までの番号を持つルールを小さい順に確認し、最初に一致したルールをそのまま適用する(#96)。

参考文献

  • [#95] AWS「Control traffic to your AWS resources using security groups」 — 原典（セキュリティグループの定義、"Security groups are stateful. …the response traffic for that request is allowed to reach the instance regardless of the inbound security group rules" という記述）
  • [#96] AWS「Control subnet traffic with network access control lists」 — 原典（NACL がサブネットレベルで通信を許可・拒否するという定義、"NACLs are stateless, which means that information about previously sent or received traffic is not saved" という記述）
  • [#97] AWS「Infrastructure security in Amazon VPC」 — 原典（「Compare security groups and network ACLs」の比較表: Level of operation(Instance level / Subnet level)、Return traffic(Automatically allowed=stateful / Must be explicitly allowed=stateless)の行、security groups を主な手段とし NACL を追加の防御層とする推奨）
