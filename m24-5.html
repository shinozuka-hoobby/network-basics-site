第 24 章 クラウドの仮想ネットワーク（VPC）　24-5

3 社で、呼び方がこう変わる

このページでわかること

ここまで見てきた区切りの考え方は、他のクラウド事業者にも近い仕組みがある。ただし、呼び方や、いくつの仕組みに分かれているかは事業者ごとに違う。このページでは、その対応関係を 1 つの表に整理する。

このページの目次

かけあい

ここまで AWS の言葉で見てきましたけど、GCP や Azure を使うときも同じことを覚え直すんですか?

考え方は同じです。呼び方が違うだけのものが多いので、表で整理しましょう。

VPC は、GCP でも同じ名前なんですか?

名前は VPC ネットワークで近いですが、範囲が違います。GCP の VPC ネットワークはリージョンをまたぐグローバルな資源で、その中のサブネットの方がリージョン単位に分かれています。

AWS だと逆に、VPC が 1 つのリージョンの中に閉じてるんでしたね。

そのとおりです。外への出口の名前も違います。GCP では、宛先 0.0.0.0/0 の経路の送り先を「default internet gateway」と呼びます。

Azure にも、似た名前の出入り口ってあるんですか?

Azure の資料には、その名前の出入り口についての記述が見当たりませんでした。表ではその欄を空欄にしています。

Azure のルートテーブルは、AWS と同じような表になってるんですか?

近い形です。Azure でも、サブネットごとにルートテーブルが自動で用意され、宛先 0.0.0.0/0 ならインターネットへ、という行が既定で入っています。

NAT ゲートウェイも、Azure にあるんですか?

あります。名前も NAT Gateway で、サブネット単位で使えます。

セキュリティグループと NACL、GCP や Azure でも 2 つ別々にあるんですか?

そこは少し違います。GCP は、通信を許可・拒否する同じ 1 つの仕組みを、サーバ単位にもサブネット単位にも使えます。区画を境界にする使い方は「サブネット分離」と呼ばれています。

Azure は?

Azure も NSG という 1 つの仕組みを、サブネットにもサーバのネットワークインタフェースにも、どちらにも適用できます。

じゃあ、AWS だけがセキュリティグループと NACL の 2 つを別々に持ってるってことですね。

そのとおりです。決めた条件に合わない通信を止めるという意味では、セキュリティグループも、GCP や Azure の同じ役目の仕組みも、どれも第 26 章で見るファイアウォールの一種です。

なるほど、名前や仕組みの分かれ方が違うだけなんですね。

そのとおりです。表の空欄は、無いと決まったわけではなく、今回集めた資料の中では確認できなかった、という意味だと考えてください。

呼び方の違いはあっても、区切って中と外を分けるっていう考え方自体は共通なんですね。

そうです。次の章では、この仕切られた範囲どうしをどうつなぐかを見ていきましょう。

まとめ

  • GCP の VPC ネットワークはグローバルな資源で、その中のサブネットはリージョン単位に分かれる。AWS の VPC は 1 つのリージョンに閉じる。
  • インターネットへの出口の名前は事業者ごとに違い、GCP では「default internet gateway」と呼ばれる。Azure は今回集めた資料に対応する記述が見つからなかった。
  • ルートテーブル・NAT ゲートウェイに近い仕組みは Azure にもある(それぞれルートテーブル、NAT Gateway)。
  • AWS はセキュリティグループと NACL を別々に持つが、GCP・Azure は同じ仕組み(ファイアウォールルール、NSG)を、サーバ単位・サブネット単位の両方に使う設計である。

GCP・Azure は、AWS のように「サーバ単位」「区画単位」で別々の仕組みを持つのではなく、同じ 1 つの仕組みを異なる単位に適用する設計になっている。GCP はファイアウォールルールの対象をタグやサービスアカウントで絞り込み、区画単位に絞る使い方を「サブネット分離」と呼ぶ。Azure は NSG 1 つを、区画にもサーバのネットワークインタフェースにも、どちらにも割り当てられる。
