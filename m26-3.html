第 26 章 ネットワークセキュリティの基礎　26-3

一斉に押し寄せる通信をどう防ぐか

このページでわかること

大量の通信を一斉に送りつけて、サーバやネットワークを使えなくしてしまう攻撃がある。攻撃には、狙う対象によっていくつかの種類がある。このページでは、その種類と、これまで見てきた仕組みによる緩和策を確認する。

このページの目次

かけあい

前のページで、大量の通信を送りつける攻撃があるって話が出ましたけど、詳しく知りたいです。

これを DDoS と呼びます。乗っ取った複数の機械から、一斉に大量の通信を送りつけて、対象を使えなくしてしまう攻撃です。

複数の機械を乗っ取るって、どうやるんですか?

不正なプログラムを送り込むなどして、遠隔から操作できるようにした機械の集まりを、ボットネットと呼びます。攻撃者はこのボットネットに一斉に指示を送ります。

攻撃の種類にはどんなものがあるんですか?

大きく 3 つあります。1 つは、帯域そのものを埋め尽くしてしまう攻撃です。

回線をパンクさせるってことですね。

そうです。大量のデータを送りつけて、対象までの回線をふさいでしまいます。

前のページで、なりすましがこの攻撃でも使われるって話がありましたけど、具体的にはどう使われるんですか?

送信元の欄を、狙った相手のアドレスに書き換えて、色々なサーバに問い合わせを送ります。すると、その返事がまとめて狙った相手に届き、通信量が膨れ上がります。

他の 2 つはどんな攻撃なんですか?

もう 1 つは、第 23 章で見たトランスポート層の弱点を突いて、ファイアウォールやロードバランサのような機器の処理能力を消耗させる攻撃です。

機器そのものを疲れさせちゃうんですね。

3 つ目は、第 20 章で見た HTTP のやり取りを大量に送りつけて、アプリケーション層でサーバに応答を作らせ続ける攻撃です。1 件あたりの処理は軽くても、大量に送られると負荷が積み重なります。

よくある事例として聞いたんですけど、DNS のサービスが DDoS 攻撃を受けて、世界中で色々なサイトにアクセスできなくなったことがあるらしいです。

2016 年に、DNS のサービスを提供する Dyn という会社が実際に DDoS 攻撃を受け、世界の広い範囲で利用者がインターネットサービスを使えなくなりました。

DNS のサーバが止まると、Web サーバ自体は無事でも困るんですね。

そのとおりです。名前解決ができなければ、利用者は IP アドレスにたどり着けません。

防ぐ方法はあるんですか?

第 22 章で見た Anycast は、通信を複数の場所に分散させられるので、大量の通信を受けたときの緩和にも役立ちます。

第 23 章で見たロードバランサも、役に立ちますか?

役立つことがあります。複数のサーバに振り分ける仕組みなので、一斉に届いた通信の負荷を分散できます。

まとめ

  • DDoS は、乗っ取った複数の機械(ボットネット)から大量の通信を送りつけ、対象のサーバやネットワークを使えなくしてしまう攻撃である。
  • DDoS には、帯域を埋め尽くす攻撃、機器の処理能力を消耗させる攻撃、アプリケーション層で負荷をかける攻撃の 3 種類がある。
  • 前のページで見た送信元の書き換えを使い、狙った相手の代わりに色々なサーバへ問い合わせを送りつけて、返事を狙った相手に集中させる手口もある。
  • 名前解決を担う DNS サーバが攻撃を受けると、Web サーバ自体は無事でも、利用者はサイトにたどり着けなくなることがある(2016 年の Dyn の例)。
  • Anycast による通信の分散や、ロードバランサによる複数サーバへの振り分けは、DDoS の影響を緩和することにも役立つ。

しくみの話

DDoS は、遠隔操作できるように乗っ取った複数の機械(ボットネット)から、対象に向けて一斉に通信を送りつける攻撃である。攻撃の種類は大きく 3 つに分けられる。1 つ目は、帯域そのものを埋め尽くす攻撃である。前のページで見た送信元の書き換えを使い、狙った相手のアドレスを名乗って色々なサーバへ問い合わせを送りつけ、その返事を狙った相手に集中させることで、この種類の攻撃を成立させる手口もある。2 つ目は、トランスポート層(L4)の弱点を突いて、ファイアウォールやロードバランサなどの機器の処理能力を消耗させる攻撃である。3 つ目は、アプリケーション層(L7)で HTTP のやり取りを大量に発生させ、サーバに応答を作らせ続けて負荷をかける攻撃である。DNS のように、名前解決という特定の役割を担うサーバが標的にされることもあり、この場合は対象の Web サーバ自体が無事でも、利用者は名前解決ができずサイトにたどり着けなくなる。Anycast による経路の分散や、ロードバランサによる複数サーバへの振り分けは、こうした攻撃の影響を抑えることにも役立つ。
