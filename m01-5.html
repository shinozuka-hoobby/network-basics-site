第 1 章 パケットの旅　1-5

封筒の重なり — PC が包み、ルータが外側だけ入れ替え、サーバが開ける

このページでわかること

1-4 で見た 5 つの段を、1 つの HTTP リクエストが実際にどう通るかを追いかける。送る側の PC では段を降りるたびに宛先などの情報が前に付け足され、途中の機器では一番外側だけが付け替えられ、受け取るサーバでは外側から順に外される。このページでは、その包まれ方と、宛先の番号が 2 種類ある理由を確認する。ここでは PC が有線でつながっている場合で見る。

このページの目次

かけあい

1-4 で、PC は 5 段を上から下へ降りると聞きました。降りるたびに、リクエストに何が起きるんですか?

段を 1 つ降りるごとに、データの前に宛先などの情報を書いた部分が付け足されます。これをヘッダと呼びます。4 段目で TCP のヘッダ、3 段目で IP のヘッダ、2 段目でイーサネットのヘッダの順に付きます。

3 回包まれるんですね。図で見たいです。

こうなります。

送るとき
(PC の中で、段を 1 つ降りるたびに付け足す)

  HTTP の中身
   → [ TCP のヘッダ | HTTP の中身 ]
   → [ IP のヘッダ
       [ TCP のヘッダ | HTTP の中身 ] ]
   → [ イーサネットのヘッダ
       [ IP のヘッダ
         [ TCP のヘッダ | HTTP の中身 ] ] ]

受け取るとき
(サーバの中で、段を 1 つ上がるたびに外す)

  [ イーサネットのヘッダ
    [ IP のヘッダ
      [ TCP のヘッダ [ HTTP の中身 ] ] ] ]
   → イーサネットのヘッダを外す
   → IP のヘッダを外す
   → TCP のヘッダを外す
   → HTTP の中身が残る

PC の中では、段を降りるたびに TCP・IP・イーサネットの順にヘッダが付け足される。サーバの中では、段を上がるたびに外側から順に外されて、最後に HTTP の中身だけが残る。

手紙を封筒に入れて、さらに別の封筒に入れるみたいですね。

近いです。そのイメージで簡略化でき、正式にはこの処理をカプセル化と呼びます。HTTP や TCP、IP のような共通の約束事はプロトコルと呼びます。

IP の封筒に入った状態のかたまりにも、名前はあるんですか?

あります。パケットと呼びます。機器から機器へ実際に運ばれるのは、このパケットがさらにイーサネットの封筒に入ったものです。

一番外側のイーサネットの封筒の宛先は MAC アドレスでしたよね。IP アドレスがあるのに、なぜもう 1 つ宛先が要るんですか?

役割が違うからです。IP アドレスは最終的な届け先、つまり相手のサーバを指します。MAC アドレスは次に渡す隣の機器を指し、PC から見れば家庭用ルータです。

じゃあ PC が送るとき、外側の封筒の宛先はサーバじゃなくて家庭用ルータなんですか?

そうです。1-4 で見たとおり、2 段目のデータリンク層は隣の機器へ渡すだけの段なので、宛先も隣の機器になります。家庭用ルータに届いた後、ルータの中でどうなるかを図で見ましょう。

区間 1: PC → 家庭用ルータ
  [ イーサネットのヘッダ
      宛先: 家庭用ルータ(MAC アドレス)
    [ IP のヘッダ
        宛先: サーバ(IP アドレス)
      [ TCP のヘッダ [ HTTP の中身 ] ] ] ]

家庭用ルータの中で
  1. 外側のイーサネットのヘッダを外す
  2. IP のヘッダの宛先を見て、
     次の送り先を決める
  3. 次の区間用のイーサネットのヘッダを付ける
  IP のヘッダから内側は、開けずにそのまま

区間 2: 家庭用ルータ → 次のルータ
  [ イーサネットのヘッダ
      宛先: 次のルータ(MAC アドレス)
        ← 付け替わった
    [ IP のヘッダ
        宛先: サーバ(IP アドレス)
        ← 変わらない
      [ TCP のヘッダ [ HTTP の中身 ] ] ] ]

途中のルータで付け替わるのは一番外側のヘッダだけ。IP のヘッダの宛先(最終的な届け先)は、何台のルータを通っても変わらない。

ルータは外側の封筒を開けて、IP の封筒の宛先を見て、次の機器宛ての新しい外側の封筒に入れ直す。中の IP の封筒は触らない、ということですか?

そのとおりです。ルータは自分が使う一番上の段、3 段目の IP のヘッダの宛先を見て次の送り先を決め、外側のイーサネットのヘッダだけを次の区間用に付け替えます。TCP のヘッダや HTTP の中身は開けません。

だから 1-4 で「ルータは IP アドレスだけを見る」だったんですね。サーバに着いたらどうなりますか?

サーバは 5 段全部を使うので、外側から順にイーサネット、IP、TCP のヘッダを外し、最後に HTTP の中身だけが残ります。これが 1-1 で見た「要求」がサーバに届いた瞬間です。

ルータが何台あっても、外側の封筒が付け替わるだけで、IP の封筒はずっと同じなんですね。

そうです。だから途中のルータが 10 台あっても、PC とサーバは相手の IP アドレスだけを気にすればよいのです。

1-4 の「下の段を差し替えても上はそのまま」ともつながりました。無線でも有線でも、外側の封筒の種類が変わるだけですね。

そのとおりです。外側の封筒の形が変わっても、IP の封筒から内側は作り直さなくてよいのが、層を分ける一番の利点でした。

今日は「PC が包み、ルータが外側だけ入れ替え、サーバが開ける」と覚えておけばいいですか?

それで十分です。ヘッダの中に実際に何が書かれているかは、第 3 章・第 6 章・第 13 章でそれぞれ開けて見ていきます。

まとめ

  • PC で段を 1 つ降りるごとに、データの前に宛先などの情報を書いたヘッダが付け足される。4 段目で TCP、3 段目で IP、2 段目でイーサネットの順で、この包む処理をカプセル化と呼ぶ。
  • HTTP や TCP、IP のような共通の約束事をプロトコルと呼び、IP の封筒に入った状態のひとかたまりをパケットと呼ぶ。
  • IP アドレスは最終的な届け先、MAC アドレスは次に渡す隣の機器を指す。途中のルータで付け替わるのは一番外側のヘッダだけで、IP のヘッダの宛先は変わらない。
  • サーバは 5 段すべてを使い、外側から順にヘッダを外して、最後に HTTP の中身を取り出す。

しくみの話

かけあいで手紙を何重にも封筒に入れることにたとえたとおり、カプセル化は段を降りるごとにデータ全体を包み、ヘッダを付け足す処理である。段ごとに使うプロトコル(共通の約束事)が決まっていて、トランスポート層では TCP のヘッダ、インターネット層(この講座のネットワーク層)では IP のヘッダが付き、IP のヘッダまで付いたひとかたまりがパケットである。その外側に、ネットワークインターフェース層(この講座のデータリンク層)で次の送信先の情報を含むヘッダが付き、受け取る側は逆の順に外す(#12)。IP のヘッダの宛先は最終的な届け先で、途中のルータは次にどこへ送るかだけを決めて外側のヘッダを付け替える(#73、#4)。ルータの中の図で外側をイーサネットとしたのは簡略化で、区間ごとに配線の約束事が違えば、外側のヘッダの種類もその区間のものになる。
