第 24 章 クラウドの仮想ネットワーク（VPC）　24-1

手順書どおりに作った、あの仕切られた範囲

このページでわかること

クラウドの中には、自分専用に仕切られたネットワークの範囲を用意できる。その範囲の中を、さらに小さな区画に分けて使う。このページでは、この仕切りと区画が、これまでの章で見た IP アドレスの範囲の区切り方と同じ考え方であることを確認する。

このページの目次

かけあい

前に、AWS の手順書をなぞって VPC を作ったことがあるんですけど、あれって結局何を作ってたんですか?

第 10 章 10-4 で少し触れましたが、今日はその中身を見ていきましょう。あなたが作ったのは、クラウドの中に用意する、自分専用の仕切られたネットワークの範囲です。これを VPC と呼びます。

仕切られた範囲、っていうのは、第 5 章で見たサブネットみたいなものですか?

近い話ですが、範囲の大きさが違います。VPC の中に、IP アドレスの範囲を指定して、サブネットを作ります。

あ、手順書で「10.0.1.0/24」みたいな数字を入力した覚えがあります。

それが、第 5 章 5-2 で見た CIDR 表記です。VPC の中でサブネットを作るときも、同じ書き方で範囲を指定します。

作った VPC の中に、最初からサブネットが用意されてたりするんですか?

アカウントによっては、最初から使える VPC とサブネットが用意されていることもあります。手順書で新しく作ったなら、自分で範囲を指定した、独自の VPC とサブネットです。

サブネットって、1 つの VPC の中にいくつも作れるんですか?

作れます。外から届く Web サーバ用の区画と、データベース用の区画のように、役割ごとに分けて作ることがあります。

なんで分けるんですか? 1 つのサブネットにまとめちゃだめなんですか?

まとめても動きますが、外から直接アクセスさせたくないサーバを、別の区画に分けて置いておける、という理由があります。

そのデータベース用の区画は、外からは直接アクセスできないようにしておく、ってことですね。

そのとおりです。次のページで、このサブネットから外に出る経路がどう決まるかを見ていきます。

そういえば、その VPC 自体は、AWS だと 1 つのリージョンに閉じてるんですか?

そうです。リージョンとは、AWS が世界各地に用意しているデータセンターの拠点のことで、AWS の VPC は 1 つのリージョンの中に閉じています。サブネットは、その VPC の中の、さらに細かい区画という位置づけです。

IPv4 だけじゃなくて、IPv6 の CIDR も設定できるんですか?

できます。VPC には、IPv4 の CIDR と、AWS が提供する IPv6 の CIDR の、両方を設定できます。IPv6 については第 11 章で見た内容がそのまま活きます。

サブネットを作っただけで、もう外のインターネットと通信できるんですか?

いいえ。区画を分けただけでは、まだ何も通信できません。次のページで、外への経路がどう決まるかを見ていきましょう。

まとめ

  • VPC は、クラウドの中に用意する、自分専用の仕切られたネットワークの範囲である。
  • VPC の中に IP アドレスの範囲を CIDR 表記で指定して、サブネットという区画を作る。第 5 章 5-2 で見た CIDR 表記と同じ書き方を使う。
  • サブネットは役割ごとに分けて作ることができ、外から直接アクセスさせたくないサーバを、別の区画に置いておける。
  • AWS の VPC は 1 つのリージョンの中に閉じており、サブネットはその VPC の中のさらに細かい区画である。

しくみの話

VPC（Virtual Private Cloud）は、クラウドの中に用意する、自分専用の仕切られたネットワークの範囲である(#22)。VPC を作るときは、IP アドレスの範囲を CIDR 表記で指定する(#22)。この範囲の中に、さらに細かい区画としてサブネットを作り、それぞれにも IP アドレスの範囲を CIDR 表記で指定する。サブネットは役割ごとに分けて作ることができ、外から直接アクセスさせたい Web サーバ用の区画と、直接アクセスさせたくないデータベース用の区画を、別のサブネットに分けて置くことがある(#97)。AWS の VPC は 1 つのリージョンの中に閉じており、サブネットはその VPC の中のさらに細かい区画という位置づけになる(#22)。アカウントによっては、あらかじめ使える VPC とサブネットが用意されていることもあるが、手順書で新しく作った場合は、自分で範囲を指定した独自の VPC とサブネットである(#22)。VPC には、IPv4 の CIDR に加えて、IPv6 の CIDR も設定できる(#22)。また、VPC 自体を、対象のワークロードや組織ごとに分けて使うこともある(#97)。
