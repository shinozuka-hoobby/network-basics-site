第 28 章 パケットキャプチャ — tcpdump と Wireshark　28-5

TCP・DNS・TLS のやり取りを、記録の中でたどる

このページでわかること

ここまでの章で見た名前解決・接続の確立・暗号化の始まりは、1 回の通信の記録を最初から最後までたどると、その順番どおりに並んでいるのが確認できる。このページは、この章のまとめとなる演習である。

このページの目次

かけあい

ここまでキャプチャフィルタや表示フィルタを見てきましたけど、実際に 1 回の通信を最初から最後まで追ってみたいです。

curl でアクセスしながら記録を取って、Wireshark でたどってみましょう。

Wireshark って、どうやって手に入れるんですか?

公式サイトからダウンロードしてインストールします。

インストールと、実際に記録する手順は、別々に考えていいですか?

はい。先にインストールを済ませておいて、それから記録・保存の手順に進む、と分けて考えると進めやすいです。

Wireshark で記録を始めるタイミングは、curl を打つ前ですか?

はい。先に記録を始めてから、curl を実行してください。あとから記録を始めると、最初の DNS の問い合わせを取り逃します。

まず何が記録されるんですか?

最初に、第 16 章で見た DNS の問い合わせと応答が記録されます。相手の IP アドレスが分からないと、次に進めないからです。

次が、第 13 章で見た TCP ハンドシェイクですね。SYN・SYN/ACK・ACK の 3 回のやり取り。

そのとおりです。その次に、第 18 章で見た TLS ハンドシェイクが始まります。最初の Client hello には、相手の名前(SNI)がまだ見えます。

その後のやり取りは、もう中身が見えないんですよね?

はい。TLS ハンドシェイクが終わると暗号化された通信になるので、記録を見ても中身は読めません。

じゃあ、HTTP の応答のヘッダとかも、記録からは見えないんですか?

見えません。中身を確認したいときは、第 20 章で見た curl 自体の出力を見ることになります。この記録で分かるのは、あくまで DNS・TCP・TLS の手順が進んだこと自体です。

Wireshark だと、この一連の流れをどうやって追うんですか?

1 回分の通信に関連するやり取りをまとめて表示する機能があります。DNS・TCP・TLS の流れを、まとめて追いやすくなります。

保存はどうすればいいですか? 28-3 で見た pcap ファイルですよね。

はい。記録が終わったら、そのままファイルに保存しておけば、あとで何度でも見返せます。

対象は、この Mac の自分の通信だけですよね?

そうです。他人の通信をのぞいたり、無線を傍受するような使い方はしません。

第 1 章で見た 4 段階が、こうして記録の中に順番どおり現れているんですね。

そのとおりです。名前解決、接続の確立、暗号化の開始という順序が、この章で見てきた道具を使えば、実際の記録の中で確認できます。

まとめ

  • curl -sI https://example.com のような通信を記録すると、最初に DNS の問い合わせと応答、次に TCP ハンドシェイク(SYN・SYN/ACK・ACK)、その次に TLS ハンドシェイクの Client hello が、この順序で記録に現れる。
  • 名前解決が終わらないと接続できず、接続が終わらないと暗号化の手続きに進めないため、この順序になる。
  • Client hello には相手の名前(SNI)がまだ見えるが、TLS ハンドシェイクが終わると暗号化された通信になり、記録を見ても中身は読めなくなる。
  • Wireshark で 1 回分の通信をまとめて表示する機能を使うと、関連するやり取りを追いやすい。記録した内容は pcap ファイルとして保存し、あとで何度でも見返せる。

しくみの話

curl -sI https://example.com のような通信を 1 回記録すると、まず第 16 章で見た DNS の問い合わせと応答が現れる。名前解決の答えが決まらなければ、相手に接続できないためである(#83)。次に、第 13 章で見た TCP ハンドシェイク、SYN・SYN/ACK・ACK の 3 回のやり取りが記録される(#71)。その次に、第 18 章で見た TLS ハンドシェイクが始まり、最初の Client hello には相手の名前(SNI)がまだ見える(#55)。TLS ハンドシェイクが終わると暗号化された通信になり、それ以降の中身は記録を見ても読めなくなる(#55)。Wireshark には、1 回分の通信に関連するやり取りをまとめて表示する機能があり、この一連の流れを追うのに使える(#48)。この記録から分かるのは DNS・TCP・TLS の手順が進んだことであり、暗号化された後の HTTP の中身までは分からない。

試してみよう

curl -sI https://example.com

見方: 先に記録を始めた状態で、このコマンドを実行してください。記録の中に、DNS の問い合わせと応答、TCP ハンドシェイク、TLS ハンドシェイクの Client hello が、この順番で並んでいるはずです。

記録を先に始めてから curl を実行する。command not found などで動かなければ、読むだけで進んでよい。
