第 28 章 パケットキャプチャ — tcpdump と Wireshark　28-2

見たいものだけを残す

このページでわかること

パケットキャプチャは、条件を付けずに実行すると、あらゆる通信が次々と記録される。記録する時点で、条件に合う通信だけに絞り込む仕組みがある。このページでは、その絞り込み方を確認する。

このページの目次

かけあい

さっき試したら、Wi-Fi のいろんな通信が次々表示されて、見たいものが埋もれちゃいました。

記録する時点で、条件に合う通信だけに絞り込めます。この仕組みをキャプチャフィルタと呼びます。

どんな条件が指定できるんですか?

相手のアドレスや、ポート番号などです。例えば port 53 と指定すると、第 16 章で見た名前解決の通信だけが残ります。

試してみます。別の窓で dig を実行すれば、問い合わせが記録されるはずですね。

そうです。53 番のポートに関する通信、つまり DNS の問い合わせと応答だけが画面に表示されます。

-n も付けてるのを見ましたけど、これは何のためですか?

-n を付けると、相手の名前ではなく IP アドレスの数字のまま表示されます。付けないと、アドレスを名前に変換しようとする分、表示までに時間がかかることがあります。

port 以外にも、条件はあるんですか?

あります。host で相手のアドレスを指定できます。tcp や udp を port の前に付ければ、プロトコルの種類とポート番号を組み合わせて絞り込めます。

host はアドレスの数字を書くんですか? それとも第 16 章で見た名前でもいいんですか?

どちらでも書けます。ただし名前を書くと、第 16 章で見た名前解決の通信が余分に発生することがあるので、アドレスの数字で指定する方が確実です。

複数の条件を組み合わせることもできますか?

できます。and でつなげば、両方の条件を満たす通信だけに絞り込めます。

例えば、特定の相手との DNS の通信だけ、みたいな絞り方もできるんですね。

そのとおりです。host と port を and でつなげば、その組み合わせに絞り込めます。

host の代わりに、相手のネットワークの範囲を指定することもできるんですか?

できます。net という条件で、指定したネットワークの範囲に含まれるかどうかで絞り込めます。パケットの大きさで絞り込む less・greater という条件もあります。

これは tcpdump だけの機能なんですか?

いいえ。Wireshark で記録を始めるときにも、同じ考え方の条件を指定できます。書き方も、tcpdump とほぼ同じです。

絞り込めば、見たい通信だけに集中できますね。

そのとおりです。記録する時点で絞り込む、キャプチャフィルタの考え方はここまでです。

記録したあとで、絞り込む条件を変えたくなったらどうするんですか?

良い質問です。次のページで、記録をファイルに保存する方法を見て、そのあとで条件を変えて見返す方法も確認しましょう。

まとめ

  • キャプチャフィルタは、記録する時点で、条件に合う通信だけに絞り込む仕組みである。tcpdump にも Wireshark にも、同じ考え方のキャプチャフィルタがある。
  • host(相手のアドレス)、port(ポート番号)を指定でき、tcp や udp を port の前に付けるとプロトコルの種類も組み合わせて絞り込める。host はアドレスの数字でも名前でも書けるが、名前を書くと名前解決の通信が余分に発生することがある。
  • and でつなぐと、複数の条件をすべて満たす通信だけに絞り込める。host と port を and でつなげば、特定の相手との、特定のポートの通信だけに絞り込める。
  • -n を付けると、アドレスを名前に変換せず、数字のまま表示する。net(ネットワークの範囲)や less・greater(パケットの大きさ)といった条件もある。

しくみの話

キャプチャフィルタは、パケットを記録する時点で、条件に合う通信だけに絞り込む仕組みである。tcpdump では host(相手のアドレス)、port(ポート番号)などの条件を指定できる(#107、#112)。host はアドレスの数字でも名前でも指定できるが、名前を指定すると自身の名前解決の通信が余分に発生することがある(#112)。tcp や udp は port の前に付けることで、プロトコルの種類とポート番号を組み合わせて指定でき、条件は and でつなぐと両方を満たす通信だけに絞り込まれる(#112「tcp port 23 and host 10.0.0.5」の例)。この他にも、net で相手のネットワークの範囲を指定したり、less・greater でパケットの大きさを条件にしたりできる(#112)。-n を付けると、送信元・宛先のアドレスを名前に変換せず、そのまま数字で表示する(#107)。

試してみよう

sudo tcpdump -i en0 -n -c 5 port 53
dig example.com

見方: 1 行目を実行して待っている間に、2 行目を別の窓で実行してください。port 53 という条件により、DNS の問い合わせと応答だけが画面に表示されます。5 個受け取ると自動的に止まります。

2 行目は 1 行目とは別のターミナルの窓で実行する。command not found などで動かなければ、読むだけで進んでよい。
