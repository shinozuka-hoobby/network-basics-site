第 2 章 信号と回線　2-2

遠い相手ほど、届くまでに時間がかかる

このページでわかること

届くまでの時間のうち、相手までの距離によって決まる部分がある。信号が伝わる速さは有限なので、遠い相手ほど時間がかかる。このページでは、その時間の正体と、送ってから返事が戻るまでの時間を実際に測る方法を確認する。

このページの目次

かけあい

さっきの海外サイトの話、なんでそんなに遅いんですか。

信号は回線の中を、ものすごく速いですが、無限の速さでは伝わりません。

どれくらいの速さなんですか。

たとえば光ファイバの中を光の信号が伝わる速さは、秒速 2 億メートルほどです。距離をこの速さで割ると、伝わるのにかかる時間が出ます。これを伝搬遅延と呼びます。

じゃあ、1,000km 離れた相手だと、どれくらいかかるんですか。

計算してみましょう。1,000km は 100 万メートルなので、100 万 ÷ 2 億 = 0.005 秒、つまり片道 5 ミリ秒ほどです。

送って、その返事が戻ってくるまでだと、その倍くらいですか。

そのとおりです。送ってから、相手からの返事が戻ってくるまでの往復の時間をRTTと呼びます。実は、あるコマンドを使うと、この時間を実際に測ることができます。

実際の回線だと、RTT はどれくらいになるものなんですか。

大陸をまたぐ経路では約 60 ミリ秒、衛星回線を使うと約 500 ミリ秒になることが知られています。同じ地球上でも、経路によって差が大きいんです。

衛星回線は、なんでそんなに時間がかかるんですか。

衛星は地上からとても高い位置にあるので、地上を這うように延びる回線に比べて、信号が往復する距離そのものが長くなるからです。

個人開発で使ってた API が、海外リージョンだけ応答が遅かったことがあります。

まさにこれが理由です。物理的な距離が長い分、伝搬遅延が大きくなります。回線をどれだけ太くしても、この時間は縮まりません。

太い回線を使っても解決しないんですね。

そうです。伝搬遅延は距離と信号の速さだけで決まり、回線の帯域幅とは無関係です。

海外のユーザー向けには、何か対策できることはあるんですか。

サーバそのものを利用者の近くに置く、という工夫があります。距離を短くできれば、伝搬遅延そのものを減らせるからです。具体的な仕組みは、第 22 章で扱います。

伝搬遅延と RTT、覚えることが増えてきました。

整理すると、伝搬遅延は片道、RTT は往復です。RTT はおおよそ、行きと帰りの伝搬遅延を足した値に近くなります。

自分の Mac からでも、この時間差を実際に確かめることはできますか。

できます。実行結果に出てくる時間を、近い相手と遠い相手で比べてみましょう。

やってみます。

では、回線の太さは何に効くのか、次のページで見ましょう。

まとめ

  • 信号は回線の中を、光の速さに近いが有限の速さで伝わる。
  • 距離を信号が伝わる速さで割った時間を伝搬遅延と呼び、距離が長いほど長くなる。回線の帯域幅を変えても短くならない。
  • 送ってから、相手からの返事が戻ってくるまでの往復の時間を RTT と呼び、実際にコマンドで測れる。
  • 実際の回線では、大陸をまたぐ経路で RTT が約 60 ミリ秒、衛星回線では約 500 ミリ秒になることが知られている。
  • 海外サイトだけ応答が遅いのは、物理的な距離が長く伝搬遅延が大きいためで、回線を太くしても解決しない。
  • サーバそのものを利用者の近くに置くなど、物理的な距離を短くする工夫ができれば、伝搬遅延そのものを減らせる。
  • 衛星回線の RTT が特に長いのは、地上の回線に比べて信号が往復する物理的な距離そのものが長いためである。

しくみの話

伝搬遅延は、信号が送り出されてから相手に届くまでにかかる時間で、距離を信号が伝わる速さで割った値になる。光ファイバの中を光の信号が伝わる速さは秒速 2×10^8 メートルほどで、真空中を進む光の速さ(秒速 3×10^8 メートル)よりやや遅い(#4)。たとえば 1,000km(100 万メートル)離れた相手なら、伝搬遅延は片道約 5 ミリ秒になる計算である。送ってから、相手からの返事が戻ってくるまでの往復の時間を RTT と呼び、おおよそ往路と復路の伝搬遅延を足した値に近い。実際の回線では、大陸をまたぐ経路で RTT が約 60 ミリ秒、衛星回線では約 500 ミリ秒になることが知られている(#4)。衛星回線が特に長いのは、地上の回線に比べて信号が往復する物理的な距離そのものが長いためである。衛星回線を使う地域では、通話や画面共有のような双方向のやり取りで、この遅れが体感されやすい。伝搬遅延は距離と信号の速さだけで決まり、回線の帯域幅(太さ)を変えても短くならないが、サーバの置き場所を変えて距離そのものを短くすれば、伝搬遅延を減らすことはできる。次の試してみようでは、近い相手と遠い相手に対する実行結果を比べることで、この関係を確かめる。

試してみよう

ping -c 3 localhost
ping -c 3 example.com

見方: 2 つの実行結果で、返ってくるまでの時間(ミリ秒)を比べてください。localhost はほぼ 0 に近い値、example.com はそれより大きい値になります。相手までの距離が長いほど、この時間が長くなることの材料として見てください。

command not found などで動かなければ、読むだけで進んでよい。
