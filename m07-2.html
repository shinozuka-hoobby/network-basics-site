第 7 章 ARP と同一ネットワーク内の通信　7-2

相手の MAC アドレスを、IP アドレスから調べる

このページでわかること

同じサブネットの相手に送るには、宛先の MAC アドレスが必要になる。しかし、相手の MAC アドレスを最初から知っていることはほとんど無い。このページでは、IP アドレスから対応する MAC アドレスを調べる仕組みを確認する。

このページの目次

かけあい

前のページで、同じサブネットならフレームの宛先に MAC アドレスが要るって話でしたけど、相手の MAC アドレスなんて最初から知らないですよね?

知りません。だから IP アドレスから調べます。この仕組みを ARP と呼びます。

3-1 でちらっと名前だけ出てきましたよね。どうやって調べるんですか、知らない相手なのに?

同じサブネットにいる機械全部に向けて、「この IP アドレスを持っているのは誰か、MAC アドレスを教えてほしい」とブロードキャストで尋ねます。

全員に聞くんですか。みんな答えちゃうんですか?

いいえ、その IP アドレスを持つ機械だけが、尋ねてきた相手に自分の MAC アドレスを返します。

尋ねる方は全員に聞くのに、答える方は 1 台だけなんですね。なんで全員答えなくていいんですか?

尋ねている内容は「この IP アドレスの持ち主」なので、当てはまらない機械が答える必要は無いんです。無駄な返事を減らせます。

尋ねるときのブロードキャストって、第 3 章で見た、宛先を 1 台に絞らない送り方のことですよね?

そのとおりです。ARP はそのブロードキャストを使って、まだ MAC アドレスを知らない相手を探しに行く仕組みです。

毎回みんなに聞くのは大変そうですね。

そのとおりです。だから一度調べた対応は、ARP キャッシュという表にしばらく覚えておきます。次に同じ相手に送るときは、聞き直さずに済みます。

あ、それって第 3 章 3-2 の試してみようで見た、あの表のことですか?

そのとおりです。あの表の正式な名前が ARP キャッシュです。IP アドレスと MAC アドレスの対応が、そこに並びます。

その表の中身は、ずっと覚えたままなんですか?

いいえ、しばらく使われなかった対応は自動的に消えます。機械をつなぎ替えたときに、古い対応がいつまでも残らないようにするためです。

じゃあ、デフォルトゲートウェイの MAC アドレスを調べたいときも、同じ仕組みが使えるんですか?

使えます。デフォルトゲートウェイも同じサブネットにいる機械の 1 台なので、同じように ARP で MAC アドレスを調べます。

なるほど、相手が本人でもデフォルトゲートウェイでも、やり方は変わらないんですね。ちなみに、ARP は別のサブネットにいる相手にも直接使えるんですか?

使えません。ARP のブロードキャストが届くのは同じサブネットの中だけです。だからこそ前のページで見たとおり、別サブネット宛てのときは、相手本人ではなくデフォルトゲートウェイの MAC アドレスを調べる必要があるんです。

前のページの判定と、このページの ARP が、やっとつながりました。

これで、宛先の MAC アドレスを調べる部品がそろいました。次のページで、1 回の送信としてつなげてみましょう。

まとめ

  • ARP は、同じサブネット内の相手の IP アドレスから、対応する MAC アドレスを調べる仕組みである。
  • 調べるときは、同じサブネットにいる機械全部にブロードキャストで尋ね、その IP アドレスを持つ機械だけが MAC アドレスを返す。
  • 一度調べた IP アドレスと MAC アドレスの対応は、ARP キャッシュという表にしばらく覚えておき、聞き直す手間を省く。
  • ARP キャッシュの中の対応は、しばらく使われないと自動的に消える。
  • デフォルトゲートウェイの MAC アドレスを調べるときも、同じ ARP の仕組みが使われる。
  • ARP のブロードキャストが届くのは同じサブネットの中だけで、別のサブネットにいる相手には直接使えない。

しくみの話

送信元の機械は、送る前に自分の ARP キャッシュを確認し、宛先の IP アドレスに対応する MAC アドレスが無ければ、同じサブネットの全機械にブロードキャストで尋ねる(#47)。尋ねられた機械はそれぞれ自分の IP アドレスと見比べ、一致する機械だけが、尋ねてきた相手に自分の MAC アドレスを返す(#3)。送信元は受け取った対応を ARP キャッシュに記録し、以後は同じ相手への送信のたびに尋ね直さずに済む。ARP キャッシュの対応は永久には残らず、しばらく使われなかったものから順に自動的に消えていく(#47)。この仕組みは相手が最終的な宛先かデフォルトゲートウェイかを区別せず、同じサブネットにいる機械であれば同じように働く。ただしブロードキャストが届く範囲は同じサブネットの中に限られるため、別のサブネットにいる相手には ARP を直接使えない(#47)。前のページで、別サブネット宛てのときにデフォルトゲートウェイの MAC アドレスを調べる理由は、この範囲の限界にある。

試してみよう

arp -a

見方: 実行結果には、近くの機械の IP アドレスと MAC アドレスの対応が並ぶ。これが、このページで見た ARP キャッシュの中身であり、第 3 章 3-2 の試してみようで見た表の正体である。
